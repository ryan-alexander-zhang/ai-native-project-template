# Spec: 桌面通知——离场时叫回用户

> 白板页面离场（页面隐藏，或窗口失焦）时，等待输入与会话结束以桌面通知
> 送达，点击回到白板并呈现该会话；页面可见且聚焦时不弹，标签页关闭后
> 有意不送达（离场即退订的边界见 §6）。路线与全部取舍见 decision-00010。

## 1. Context

- canonical terms 见 `CONTEXT.md`：白板、节点、Agent 会话、会话面板、
  等待输入、终止、刷新、就近关闭。
- 本 spec 的 Markdown 方言取 GFM。
- 输入：`parent` 为 [prd-00001-docs-whiteboard](../prd/prd-00001-docs-whiteboard.md)；
  技术路线调研为 [analysis-00001-out-of-board-notifications](../analysis/analysis-00001-out-of-board-notifications.md)；
  全部取舍在案于 [decision-00010-whiteboard-desktop-notifications](../decision/decision-00010-whiteboard-desktop-notifications.md)
  （推翻 `decision-00009` §2 第 8 条的范围外维持，已原地追注）。
- 本 spec 是 `spec-00001` … `spec-00003` 的**并列新 spec**（Sizing and
  Splitting 第 1 条），同 `parent`，不 supersede 任何一份。
- **与 `spec-00003` 的关系**：其 §6 原「板外通知」条目的**桌面通知半边**
  由本 spec 接管（邮件等其他板外通道仍范围外）；该条目已经其第十七轮
  修订轮改写为仅余邮件半边（plan-00019 T2）。事件源不新增：等待输入置位即
  `spec-00003-FR-6` 的判定、结束事件即 `spec-00003-FR-7` 的触发集，页面
  经既有刷新通路获知——**无任何服务端改动**（`decision-00010` §5 站立
  约束）。
- 后台标签被浏览器冻结或丢弃时，通知**可能不送达**（页面脚本已被终止，
  恢复时不补发）——弱语义允许，`decision-00010` §2 第 7 条；边界记于 §6。
- 随接收需修订 `CONTEXT.md` 两条既有定义：「等待输入」的「只驱动徽标与
  通知」明确为「徽标、提示条与桌面通知」；「变更推送」的 _Avoid_
  「推送通知」加注与桌面通知的区分。
- 本 spec 新增术语（拟，接收后进 `CONTEXT.md`）：
  - **桌面通知（Desktop Notification）**：白板页面离场时经浏览器原生
    通知能力弹出的系统级通知，只含会话种类、文档 id 与状态；显式开关
    启用，页面可见且聚焦时不弹，标签页关闭后不送达。
    _Avoid_：系统通知、浏览器通知、推送通知（那是变更推送词条排除的词）。
  - **离场（Away）**：白板页面不在用户眼前的状态——页面隐藏（标签页
    后台等），或页面所在窗口失焦（在别的窗口干活）；两个信号的具体
    判定口径属 design。
    _Avoid_：不在线（会话与服务都还在）、后台（只覆盖隐藏半边）。

## 2. Stories

| Story | Value | Delivers |
| --- | --- | --- |
| S1 | 作为文档负责人，我要一个显式的桌面通知开关，开启才授权、开关状态记住、关掉立即安静，这样不被未经请求的权限框和不想要的通知骚扰 | spec-00004-FR-1 |
| S2 | 作为文档负责人，我在别的窗口干活时（白板页面后台或失焦）要被「会话在等我」「会话结束了」叫回来——包括我离开时它就已经在等的那种，点一下通知就落到那个会话上 | spec-00004-FR-2, spec-00004-FR-3, spec-00004-FR-5 |
| S3 | 作为文档负责人，我看着页面时不要被重复打扰，同一个会话不要叠一摞通知，通知里也不要带正文内容 | spec-00004-FR-4, spec-00004-FR-6 |

## 4. System Requirements

- **spec-00004-FR-1** (Complex) 系统应在顶栏提供「桌面通知」开关，缺省
  关闭。当用户开启时：浏览器权限未定则请求之——授予则开关生效，拒绝则
  开关回落并提示到浏览器设置手动开启；权限此前已授予则**不再请求**、
  直接生效。当用户关闭时：立即停止弹桌面通知。开关状态（开或关）持久
  于浏览器本地（不入 `docs/`，下次打开保持）。除开启动作外，系统不得
  在任何时点请求通知权限。
- **spec-00004-FR-2** (Complex) 当会话转入等待输入（`spec-00003-FR-6`
  的置位经刷新到达页面）、开关生效且页面处于离场态时，系统应弹桌面
  通知，内容含会话种类、目标文档 id 与等待输入状态；当页面**转入离场**
  且此刻已有会话处于等待输入时，系统应为每个等待中的会话补发一条。
  等待通知的判重以**离场区间**为界：每会话一次离场区间内至多一条，再弹
  一条须用户已回到页面**且**该会话经历新的置位——不以 `spec-00003-FR-6`
  标志的逐次翻转为界（未锁存的标志遇任何输出即解除、静默即再置位，而
  CLI 停在空闲提示符上仍会自行打印，一次等待到达页面可现一连串翻转，
  issue-00020 实测；该前提经 `decision-00011` 收窄——锁存后翻转只余
  信号到达前的窗口与不发该序列的 CLI，判重语义不变、不得因信号通路
  移除）；真正的新一轮等待必经用户输入，而输入只经白板终端
  到达。多个会话相继转入等待时逐会话各一条；等待解除不通知。
- **spec-00004-FR-3** (Event) 当会话结束（触发集同 `spec-00003-FR-7`：
  正常退出、失败、含启动失败）、开关生效且页面离场时，系统应弹桌面
  通知，内容含会话种类、目标文档 id 与结束态；多个会话相继结束时逐
  会话各一条。（「终止」在实践中总在页面可见时发起、被 FR-4 抑制，
  服务端关停的结束不经本通路送达——边界见 §6。）
- **spec-00004-FR-4** (Unwanted) 若开关未启用、权限非授予态（含授权后
  被浏览器收回）、或页面可见且聚焦（非离场），系统应不弹桌面通知——
  页面内提示条与徽标照旧（`spec-00003` 语义不变）；权限被收回时静默
  降级：不重复请求权限、不报错，用户回到页面时开关呈现未生效态。
- **spec-00004-FR-5** (Event) 当用户点击一条桌面通知时，系统应**请求**
  聚焦白板页面（能否前置属浏览器与系统策略，尽力而为），并在页面呈现
  时在终端面板呈现对应会话——目标文档仍在图上时定位并选中其节点，
  不在图上时仅呈现终端并提示、当前选中与视口不变（就近处置，与
  `spec-00003-FR-4` 的面板点击同构）；对应会话已不在本次服务运行的
  列表中时（如服务已重启），提示且不改变当前视图。页面已经可见时点击
  同样呈现该会话。
- **spec-00004-FR-6** (Ubiquitous) 桌面通知的内容应只含会话种类、目标
  文档 id 与状态，不含文档正文或会话转写的任何片段（通知会落系统通知
  中心，最小化外泄面）；同一会话同刻至多一条，**后到替换先到**——替换
  由页面自己完成、不依赖通知标识的平台语义（原「复用同一标识」的写法
  即 issue-00019 的缺陷来源，据实校正；等待通知被该会话的结束通知替换）。

**Acceptance (GWT)**

- **spec-00004-AC-1.1** (spec-00004-FR-1)
  Given 开关关闭且浏览器权限未定
  When 用户开启开关且浏览器授予权限
  Then 开关生效，重新打开白板后仍为生效态
- **spec-00004-AC-1.2** (spec-00004-FR-1)
  Given 开关关闭
  When 用户开启开关且浏览器拒绝权限
  Then 开关回落为关闭并提示到浏览器设置手动开启
- **spec-00004-AC-1.3** (spec-00004-FR-1)
  Given 从未开启过开关
  When 打开白板并运行会话至等待输入
  Then 开关呈现关闭态，且不产生任何权限请求
- **spec-00004-AC-1.4** (spec-00004-FR-1)
  Given 开关关闭而浏览器权限此前已授予
  When 用户开启开关
  Then 不产生新的权限请求，开关直接生效
- **spec-00004-AC-1.5** (spec-00004-FR-1)
  Given 开关生效
  When 用户关闭开关，随后页面离场期间一个会话结束
  Then 不弹桌面通知；重新打开白板后开关仍为关闭态
- **spec-00004-AC-2.1** (spec-00004-FR-2)
  Given 开关生效且页面离场
  When 一个会话被判定为等待输入
  Then 弹出桌面通知，含其会话种类、目标文档 id 与等待输入状态
- **spec-00004-AC-2.2** (spec-00004-FR-2)
  Given 一条等待输入通知已弹出
  When 该会话继续产出（等待解除）
  Then 不弹新的桌面通知
- **spec-00004-AC-2.3** (spec-00004-FR-2)
  Given 开关生效、页面可见且一个会话已处于等待输入
  When 页面转入离场
  Then 为该会话补发一条等待输入通知，且同一次离场区间内不再补第二条
- **spec-00004-AC-2.4** (spec-00004-FR-2)
  Given 开关生效且页面离场
  When 两个会话相继转入等待输入
  Then 各得一条桌面通知
- **spec-00004-AC-2.5** (spec-00004-FR-2)
  Given 一个会话的一次等待已通知过、用户已回到页面并作答、其等待随后解除
  When 该会话再次转入等待输入且页面处于离场态
  Then 为这一次新的等待再弹一条桌面通知——回来过且有新置位即新的一次，
   不因已通知过前一次而被判重（issue-00018 的验收缺口补钉，issue-00020
   收紧 Given）
- **spec-00004-AC-2.6** (spec-00004-FR-2)
  Given 开关生效、页面离场、某会话的一次等待已通知过
  When 用户未回到页面，而该会话的等待标志反复解除又置位（CLI 空闲重绘）
  Then 不再弹新的桌面通知——该次离场至多一条（issue-00020）
- **spec-00004-AC-3.1** (spec-00004-FR-3)
  Given 开关生效且页面离场
  When 一个会话自然结束
  Then 弹出桌面通知，含种类、文档 id 与结束态
- **spec-00004-AC-3.2** (spec-00004-FR-3)
  Given 开关生效且页面离场
  When 一个会话启动失败
  Then 同样弹出桌面通知且状态为失败
- **spec-00004-AC-3.3** (spec-00004-FR-3)
  Given 开关生效且页面离场
  When 两个会话相继结束
  Then 各得一条桌面通知
- **spec-00004-AC-4.1** (spec-00004-FR-4)
  Given 开关生效、页面可见且聚焦
  When 一个会话结束
  Then 不弹桌面通知，页面内提示条照常出现
- **spec-00004-AC-4.2** (spec-00004-FR-4)
  Given 开关关闭且页面离场
  When 一个会话等待输入
  Then 不弹桌面通知，回到页面时徽标照常
- **spec-00004-AC-4.3** (spec-00004-FR-4)
  Given 开关曾生效、权限已被浏览器收回
  When 页面离场期间两个会话相继结束、用户随后回到页面
  Then 期间不弹任何通知、不产生新的权限请求，回到页面时开关呈现未生效态
- **spec-00004-AC-5.1** (spec-00004-FR-5)
  Given 一条会话通知已弹出且该会话仍在列表中、目标文档在图上
  When 用户点击该通知
  Then 页面呈现时终端面板呈现该会话、目标节点被定位选中（聚焦请求已发出）
- **spec-00004-AC-5.2** (spec-00004-FR-5)
  Given 一条会话通知已弹出、其会话已随服务重启不在列表中
  When 用户点击该通知
  Then 提示该会话已不在，当前视图不变
- **spec-00004-AC-5.3** (spec-00004-FR-5)
  Given 一条会话通知已弹出、其会话仍在列表中但目标文档已不在图上
  When 用户点击该通知
  Then 终端面板呈现该会话并提示目标不在图上，当前选中与视口不变
- **spec-00004-AC-6.1** (spec-00004-FR-6)
  Given 一个目标文档正文含敏感内容、其会话转写含长输出
  When 该会话的等待与结束通知弹出
  Then 通知内容恰为种类、文档 id 与状态，不含正文或转写片段
- **spec-00004-AC-6.2** (spec-00004-FR-6)
  Given 一个会话以启动失败结束
  When 其通知弹出
  Then 内容同样只含种类、文档 id 与失败状态，不含错误堆栈
- **spec-00004-AC-6.3** (spec-00004-FR-6)
  Given 一个会话的等待输入通知已弹出且页面仍离场
  When 该会话结束
  Then 结束通知替换等待通知——该会话同刻只有一条桌面通知

## 6. Out of Scope

- Web Push / Service Worker / Declarative Web Push——多人形态的将来轮
  （`decision-00010` §3；本轮路线是其台阶）
- 服务端直发系统通知（`decision-00010` §3 否决）
- 标签页关闭、浏览器退出后的**送达**——有意不做（离场即退订）；页面
  关闭后遗留在通知中心的旧通知，点击无效（处理器随页面消亡）——已知
  边界
- 「终止」的桌面通知在实践中不可达：终止总在页面可见时发起（被 FR-4
  抑制），服务端关停的结束随通道关闭不送达——不为其造第二条通路
- 被浏览器冻结/丢弃的后台标签：通知可能**不送达**且恢复时不补发（弱
  语义；回到页面时徽标与面板仍如实）
- 回到页面但**未作答**又离开：期间标志若有新置位，下一次离场区间可再获
  一条同一等待的通知——判重以离场区间为界的已知边界，宁噪勿静
  （issue-00020 §6；锁存后该新置位对发信号的 CLI 几乎不再发生，同一
  等待不再被提醒——损失经域主裁定接受，`decision-00011` §2 第 7 条）
- 跨窗口去重（多窗口同开重复弹为已知边界，`decision-00010` §2 第 7 条）
- 邮件等其他板外通道（`spec-00003` §6 原条目的另一半，仍范围外）
- 逐事件种类的通知偏好细分（一个总开关）
