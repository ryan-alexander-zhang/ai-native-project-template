# Spec: 并行 Agent 会话与会话面板

> 解除白板「同时仅一个 agent 会话」的 MVP 约束：多个节点可并行发起会话，
> 顶栏会话面板总览每个会话的目标文档与状态（运行中 / 等待输入 / 已结束），
> 终端可收起、可切换，会话等待输入与结束时主动通知。

## 2. Stories

## 4. System Requirements

- **spec-00003-FR-1** (Complex) 当用户发起推进、澄清、审计或共写
  （末项第二十二轮增，`spec-00006`；终端形态会话自此四种 = 推进、
  澄清、审计、共写，本 spec 各条的「终端形态」一律按此集合读），且目标
  文档没有运行中的终端形态会话（答疑会话不计）、运行中会话总数未达
  上限（FR-3）时，系统应按 `spec-00001` 的既有会话语义启动该会话，
  不受其他运行中会话影响；每个会话独立持有自己的终端通道
  （`spec-00001-FR-12` 的流式呈现与尺寸同步逐会话适用），输出与输入
  互不串流。四种终端形态会话一视同仁，无按种类的额外互斥
  （`decision-00009` §2 第 2 条）。（第二十一轮：答疑的准入由
  `spec-00005-FR-6` 持有——不占目标文档、无终端通道，总数上限 FR-3
  仍适用。）并行推进无撞号：id 在发起时由
  服务端串行分配（`spec-00001-FR-11` 的任务指令携带 id），且**已分配给
  发起中会话的 id 参与后续取号**——`rule-00001-BR-18` 的「现有最大编号」
  在有发起中会话时计入保留中的号，即便其文件尚未落盘。发起被拒的两种
  情形是 Unwanted 条款，分别由 FR-2（同文档互斥）与 FR-3（总数上限）
  持有。
- **spec-00003-FR-2** (Unwanted) 若目标文档已有运行中的终端形态会话，对该
  文档再次发起终端形态会话（推进、澄清、审计、共写——末项第二十二轮
  增）应被拒绝（含与运行中会话
  不同种类的发起；第二十一轮：答疑不在此列——发起答疑不被本条拒，运行中
  的答疑也不构成本条的占用，`spec-00005-FR-6`），拒绝以
  提示呈现原因且原因指明同文档互斥（与 FR-3 的上限原因可区分），不影响
  运行中的会话；重复发起同样被拒绝，不产生额外副作用。推进会话的「目标
  文档」取其**来源文档**（`spec-00001-FR-19` 的既有口径），故同一来源的
  两次并行推进同样被拒。互斥只及目标文档自身，不扩展到其关系文档
  （`decision-00009` §3 否决了关系文档互斥）。该文档的发起入口在其会话
  运行期间禁用（标注统一提交入口除外——提交入口不随同文档互斥整体
  禁用，其拒绝按 `spec-00007-FR-10` 在提交时逐通路判定：issue 拦下、
  question 照常，GWT 由 `spec-00007-AC-10.1` 承载；第二十三轮，同
  答疑在本条与 FR-1 的排除先例），
  悬停或聚焦时呈现同文档互斥原因，会话结束恢复可用——
  原因说明与「无下一步」说明的优先级沿 `spec-00001-FR-49` 的既有约定。
- **spec-00003-FR-3** (Unwanted) 若运行中会话总数已达上限，再次发起任何会话
  应被拒绝并说明原因（指明达到上限），已有会话不受影响；重复发起同样被
  拒绝；任一会话结束后即可再发起。上限由流程配置新键 `max_sessions`
  声明，缺省 3；声明值非正整数时按 `spec-00001-FR-15` 的启动校验拒绝
  启动并指明；键缺失时取缺省值、正常启动。槽位在服务端**受理发起时**
  占用——多次发起竞争最后一个槽位时按接收顺序先到先得，后到者按本条
  拒绝；启动失败（`spec-00001-FR-16`）即释放槽位，故失败的会话不计入
  运行中总数。上限为 1 时行为退化为单会话，面板、徽标与切换 UI 照常
  存在、无特殊分支。达上限期间各发起入口禁用并呈现上限原因（标注统一
  提交入口除外——提交入口不随总并发上限整体禁用，其拒绝在提交时逐
  通路判定：issue 整体拦下按 `spec-00007-FR-10`（`spec-00007-AC-10.3`
  承载），question 逐条拦下按 `spec-00007-FR-6`（`spec-00007-AC-6.3`
  承载）；第二十三轮，`spec-00005-FR-6` 为答疑登记排除的同型先例——
  答疑本身仍占本条名额），任一会话结束恢复可用。
- **spec-00003-FR-4** (Complex) 系统应在顶栏提供会话面板入口，入口呈现
  「运行中数/上限」；面板列出全部运行中会话与本次服务启动以来的已结束
  会话（全部历史仍归 `spec-00001-FR-54` 的会话历史，两者分工由
  `decision-00009` §2 第 6 条持有），每项含会话种类、目标文档 id、状态
  与发起时间；流程配置声明多于一条 agent 时另含所用 agent（值取
  `spec-00001-FR-54` 的会话元数据，呈现门限沿 `spec-00001-FR-55`
  「仅多于一条时呈现」的口径）；状态取运行中、等待输入、已结束，
  已结束区分正常退出、失败与终止——启动失败的会话以「失败」入面板。
  当用户点击一项时，系统应在终端面板呈现该会话（答疑项第二十一轮起改呈
  其问题列表并定位线程，`spec-00005-FR-9`），且目标文档仍在图上时
  定位并选中其节点；目标已不在图上时仅呈现终端并提示，不改变当前选中
  （就近关闭的口径）。无任何会话时面板呈现空态，入口仍在。
- **spec-00003-FR-5** (Complex) 当存在运行中会话时，终端面板一次呈现其中
  一个会话；经会话面板切换呈现时，各会话保留各自完整输出与滚动位置；
  收起终端面板不影响任何会话运行；「当前呈现的会话」与各会话滚动位置属
  呈现状态——刷新后按会话保持，所指会话已不存在时按就近关闭处置。终端
  面板头部的终止入口（`spec-00001-FR-49`）作用于当前呈现的会话，其拒绝
  语义（无运行中、已结束、重复终止）**逐会话**判定，不受其他会话存在与
  否影响。未呈现的会话不下发尺寸帧——这是对「会话有终端接入才有尺寸」
  的**新约定**（`spec-00001-FR-12` 只定义了退化尺寸不下发，没有多会话
  概念）；重新呈现时同步当前尺寸。（第二十一轮：答疑会话无终端——不
  参与本条的呈现、滚动与尺寸语义；其终止入口在会话面板逐项提供，
  `spec-00005-FR-7`。）
- **spec-00003-FR-6** (Complex) 系统应经两条通路把运行中的终端形态会话
  判定为等待输入（第十八轮修订，`decision-00011`；第二十一轮：答疑
  kind 排除于两条通路之外——headless 调用无可等的交互输入，静默是
  思考不是等待，`spec-00005-FR-6`）。**静默通路（主判定）**：当运行
  中会话连续无输出达到静默阈值且进程存活时置位。**信号通路（锁存）**：
  当会话输出流中出现终端通知转义序列（OSC 777 notify，即以
  `ESC]777;notify;` 起头的序列；只识别序列本身，标题与正文不解析；序列
  跨多个输出块到达不影响识别，缓冲实现属 design）且进程存活时立即置位并
  **锁存**；已锁存时再次出现该序列不产生额外效果。**信号识别先于输出
  解除**：含信号序列的输出块只置位并锁存、不触发解除，同一块中序列前后
  的其余字节亦不解除。两条通路的置位呈现相同：会话面板中该项状态转为
  等待输入，顶栏会话面板入口呈现等待计数徽标（以非颜色手段可辨，计数随
  等待中会话数增减）；进程已退出的会话不入判定，两条通路皆然。解除：
  未锁存时，该会话继续产出或结束即解除（现行弱语义）；已锁存时，仅用户
  向该会话的终端输入（**任一次写入**即解除，无需提交——半途停手由静默
  通路重新置位兜住，`decision-00011` §2 第 6 条）或会话结束解除——后续
  输出（状态栏重绘、插件行等空闲重绘）不解除；未被呈现的会话得不到终端输入，其锁存在被呈现并输入
  前保持（锁存语义的自然推论）；任一解除后静默通路照常重新武装。计数为
  零时徽标不呈现（沿 `spec-00002-FR-14` 诊断计数「为零不渲染」的零态
  口径）。判定整体仍取弱语义、允许误报——标记只驱动徽标与通知，不驱动
  状态流转或 commit（`decision-00009` §2 第 7 条，经 `decision-00011`
  细化）；静默阈值是实现常数（量级 10s），属 design，不进配置；信号缺失
  不影响判定（不发该序列的 CLI 只走静默通路，行为即现行）。
- **spec-00003-FR-7** (Event) 当任一会话结束（自然退出或终止）或启动失败
  （`spec-00001-FR-16`）时，系统应以
  提示条通知，内容含会话种类、目标文档 id 与结束态；多个会话相继结束时
  提示条逐条堆叠、不合并。会话面板中该项转入已结束。通知不要求终端面板
  正在呈现该会话；既有逐会话收尾——`spec-00001-FR-14` 的一会话一
  commit、刷新、`spec-00001-FR-54` 的历史落盘——照常执行且恰执行一次，
  不因通知而改变（第二十一轮：答疑会话无 commit 收尾，其余照常，
  `spec-00005-FR-4`）。
- **spec-00003-FR-8** (Event) 当多个会话相继或同时结束时，各会话的收尾应
  逐会话完成、互不吞并：产生了 `docs/` 变更的会话**至多**得到一次自己的
  commit——其变更或经自己的 commit 入库，或按下述归属边界并入先结束者
  的 commit（机制取「会话前快照」并把它从推进会话推广到终端形态会话
  ——第二十一轮起答疑除外，见下括注；共写第二十二轮入列且其快照为
  内容快照、收束另经过滤，`spec-00006-FR-6`；`CONTEXT.md` 修订项见
  Context）；收尾时无残余的会话不产生 commit。白板发起的全部 commit——会话结束 commit 与用户动作
  commit（`spec-00001-FR-14`）——进同一串行队列，互不吞并（第二十一轮：
  答疑会话不作会话前快照、不进本条通路，`spec-00005-FR-4`）。并行会话在
  **对方快照之后**写入的路径，残余归属按结束顺序：先结束者的 commit 允许
  含对方已写入的变更——同一文件与不同文件皆然（内容差集不携带归属，这是
  该机制的固有边界，实现轮定），后结束者收尾时无残余则照「无变更」处置、
  不产生 commit；变更不丢失、commit 不吞并的保证不变。以上作为已知噪音
  接受（`decision-00009` §2 第 9 条及其推广追注）。同批结束触发的刷新应
  合并为一次，呈现状态按既有语义保持。收尾的串行化机制属 design。
- **spec-00003-FR-9** (State) 当浏览器与白板断开连接时，全部运行中会话应在
  服务端存续；当白板重新打开时，会话面板应列出全部运行中会话，用户可逐一
  回到各会话终端（含此前输出）继续交互；断开期间已结束的会话应呈现为已
  结束，且其收尾已照常完成（扩展 `spec-00001-FR-21` 到多会话）。服务端
  自身**正常关停**时，系统应对每个运行中会话执行终止的收尾（结束进程、
  commit 与历史落盘；「终止」一词已扩义涵盖此情形，见 `CONTEXT.md`）；
  跨服务重启的会话存续不做承诺（异常崩溃不保证收尾），重启后面板按空态
  起步（`decision-00009` §2 第 10 条）。
- **spec-00003-FR-10** (Complex) 目标文档的节点应呈现其会话状态标记，运行中
  与等待输入两态可辨且互相可区分（均以非颜色手段）；当用户激活标记时，
  系统应在终端面板呈现该会话（与 FR-4 的点击同构。第二十一轮：同文档可
  多会话——存在终端形态会话时呈现它，仅答疑运行时改呈问题列表，标记不
  逐会话计数，口径由 `spec-00005-FR-9` 持有）；会话结束后标记随刷新
  消失。标记只作用于呈现层：不产生关系边、不进解析诊断（沿
  `spec-00001-FR-59` 的口径）。（spec-00010 追注：折叠的目录组把组内文档的
  标记聚合到组节点，激活只展开目录组，`spec-00010-FR-5`/`FR-6`。）

**Acceptance (GWT)**

- **spec-00003-AC-1.1** (spec-00003-FR-1)
  Given 一份文档的澄清会话运行中
  When 对另一份文档发起审计
  Then 第二个会话启动，第一个会话不受影响，两者各自的终端可分别交互
  （第二十一轮换例：原以答疑为例，其形态已无终端、移交 `spec-00005`）
- **spec-00003-AC-1.2** (spec-00003-FR-1)
  Given 两个会话并行运行中
  When 其中一个产生输出、用户同时在另一个的终端输入
  Then 输出只出现在产出会话自己的终端与转写中，输入只转发给被输入的
   会话，两者互不串流
- **spec-00003-AC-1.3** (spec-00003-FR-1)
  Given 两份不同来源文档各自发起的推进会话并行运行中
  When 两个会话各自产出新文档
  Then 两份新文档的 id 互不相同（发起时已由服务端串行分配）
- **spec-00003-AC-2.1** (spec-00003-FR-2)
  Given 一份文档的推进会话运行中
  When 对同一份文档发起澄清
  Then 请求被拒绝且原因指明同文档互斥，运行中的推进会话不受影响
  （第二十一轮换例：原 Given 是答疑会话——答疑已不占文档，该方向的
  反面断言由 `spec-00005-AC-6.2` 持有）
- **spec-00003-AC-2.2** (spec-00003-FR-2)
  Given 对同一份文档的发起已被拒绝一次
  When 再次对该文档发起会话
  Then 再次被拒绝，且不产生任何额外副作用（无会话、无 commit）
- **spec-00003-AC-2.3** (spec-00003-FR-2)
  Given 一份文档的会话运行中，另一份文档与它有关系边相连
  When 对另一份文档发起会话
  Then 会话正常启动（互斥不扩展到关系文档）
- **spec-00003-AC-2.4** (spec-00003-FR-2)
  Given 一份文档的会话运行中
  When 悬停或聚焦该文档的发起入口
  Then 入口呈禁用态并呈现同文档互斥的原因说明；该会话结束后入口恢复可用
- **spec-00003-AC-2.5** (spec-00003-FR-2)
  Given 一份文档的会话已结束
  When 再次对该文档发起会话
  Then 会话正常启动
- **spec-00003-AC-2.6** (spec-00003-FR-2)
  Given 一份文档的推进会话运行中
  When 从同一文档向另一个下一步类型再次发起推进
  Then 请求被拒绝且原因指明同文档互斥（推进的目标文档取来源文档）
- **spec-00003-AC-2.7** (spec-00003-FR-2)
  Given 一份文档的共写会话运行中
  When 对同一份文档发起澄清
  Then 请求被拒绝且原因指明同文档互斥，运行中的共写会话不受影响
  （第二十二轮增——design-00001 §11.4 的「无需新判」依赖本向）
- **spec-00003-AC-2.8** (spec-00003-FR-2)
  Given 一份文档的推进会话运行中
  When 对同一份文档发起共写
  Then 请求被拒绝且原因指明同文档互斥（第二十二轮增，反向）
- **spec-00003-AC-3.1** (spec-00003-FR-3)
  Given 运行中会话总数已达上限
  When 对一份无会话的文档发起答疑
  Then 请求被拒绝且原因指明达到上限，已有会话全部不受影响
- **spec-00003-AC-3.2** (spec-00003-FR-3)
  Given 运行中会话总数已达上限且一次发起已被拒绝
  When 不等任何会话结束再次发起
  Then 再次被拒绝，且不产生任何额外副作用
- **spec-00003-AC-3.3** (spec-00003-FR-3)
  Given 运行中会话总数已达上限
  When 其中一个会话结束后再次发起
  Then 会话正常启动
- **spec-00003-AC-3.4** (spec-00003-FR-3)
  Given 流程配置的 `max_sessions` 声明为非正整数
  When 启动白板
  Then 拒绝启动并指明该键非法
- **spec-00003-AC-3.5** (spec-00003-FR-3)
  Given 流程配置未声明 `max_sessions`
  When 启动白板
  Then 正常启动，上限取缺省值 3
- **spec-00003-AC-3.6** (spec-00003-FR-3)
  Given 上限仅剩一个槽位
  When 两次发起几乎同时到达服务端
  Then 先到者启动，后到者被拒绝且原因指明达到上限
- **spec-00003-AC-3.7** (spec-00003-FR-3)
  Given 所选 agent CLI 不存在，发起的会话启动失败
  When 随后再发起其他会话
  Then 失败的会话不计入运行中总数，随后的发起不因它受限
- **spec-00003-AC-3.8** (spec-00003-FR-3)
  Given `max_sessions` 声明为 1 且一个会话运行中
  When 对另一份文档发起会话
  Then 按上限拒绝；会话面板、徽标与终端切换 UI 照常存在、无特殊分支
- **spec-00003-AC-4.1** (spec-00003-FR-4)
  Given 两个会话运行中、一个会话已正常结束、一个会话已被终止
  When 打开会话面板
  Then 四项俱在，每项含会话种类、目标文档 id、状态与发起时间，两个已结束
   项分别标明正常退出与终止
- **spec-00003-AC-4.2** (spec-00003-FR-4)
  Given 本次服务启动以来没有任何会话
  When 打开会话面板
  Then 面板呈现空态，入口照常可用
- **spec-00003-AC-4.3** (spec-00003-FR-4)
  Given 会话面板中有一项运行中会话且其目标文档在图上
  When 点击该项
  Then 终端面板呈现该会话，视口定位并选中目标文档节点
- **spec-00003-AC-4.4** (spec-00003-FR-4)
  Given 会话面板中有一项会话，其目标文档已从磁盘删除且图已刷新
  When 点击该项
  Then 终端面板呈现该会话并提示目标不在图上，当前选中与视口不变
- **spec-00003-AC-4.5** (spec-00003-FR-4)
  Given 上限为 3 且两个会话运行中
  When 查看顶栏会话面板入口
  Then 入口呈现 2/3
- **spec-00003-AC-4.6** (spec-00003-FR-4)
  Given 一个会话因 agent CLI 不存在而启动失败
  When 打开会话面板
  Then 该会话以「失败」呈现于已结束项中
- **spec-00003-AC-4.7** (spec-00003-FR-4)
  Given 一个会话进程以非零退出码退出
  When 打开会话面板
  Then 该项呈现为已结束且标明失败
- **spec-00003-AC-4.8** (spec-00003-FR-4)
  Given 流程配置声明两条 agent，一个会话运行中
  When 打开会话面板
  Then 该项含所用 agent
- **spec-00003-AC-4.9** (spec-00003-FR-4)
  Given 流程配置恰声明一条 agent，一个会话运行中
  When 打开会话面板
  Then 该项不含所用 agent（沿「仅多于一条时呈现」口径）
- **spec-00003-AC-5.1** (spec-00003-FR-5)
  Given 两个会话运行中，终端正呈现会话 A
  When 经会话面板切换到会话 B 再切回 A
  Then A 的完整输出与滚动位置保持，期间两个会话都未中断
- **spec-00003-AC-5.2** (spec-00003-FR-5)
  Given 一个会话运行中
  When 收起终端面板直至该会话自然结束
  Then 会话照常运行至结束，收尾（commit、刷新、落盘）照常执行
- **spec-00003-AC-5.3** (spec-00003-FR-5)
  Given 两个会话运行中，终端正呈现会话 A
  When 执行终止
  Then 仅 A 被终止并走一次退出收尾，B 照常运行
- **spec-00003-AC-5.4** (spec-00003-FR-5)
  Given 无任何会话、终端面板未呈现
  When 发起第一个终端形态会话
  Then 终端面板呈现该会话并开始流式输出（第二十一轮收窄：发起答疑不
  触发终端呈现，其反面由 `spec-00005-AC-3.4` 断言）
- **spec-00003-AC-5.5** (spec-00003-FR-5)
  Given 终端正呈现已结束的会话 A，另有会话 B 运行中
  When 执行终止
  Then 请求被拒绝（A 已结束，逐会话判定），B 照常运行且不受影响
- **spec-00003-AC-5.6** (spec-00003-FR-5)
  Given 终端正呈现会话 A 且用户已滚动至历史输出中部
  When 变更推送触发刷新
  Then 终端仍呈现 A，滚动位置不变（呈现状态按会话保持）
- **spec-00003-AC-5.7** (spec-00003-FR-5)
  Given 两个会话运行中，终端正呈现会话 A
  When 终端面板尺寸变化后经会话面板切换到会话 B
  Then 尺寸帧仅曾下发给 A；切换时 B 得到当前尺寸的同步
- **spec-00003-AC-6.1** (spec-00003-FR-6)
  Given 一个运行中会话连续无输出达到静默阈值且进程存活
  When 系统判定其等待输入
  Then 会话面板中该项状态转为等待输入，顶栏入口呈现等待计数徽标
- **spec-00003-AC-6.2** (spec-00003-FR-6)
  Given 一个会话经静默通路置位等待输入、未锁存
  When 用户在其终端回答后会话继续产出
  Then 该项状态回到运行中，等待计数随之减少
- **spec-00003-AC-6.3** (spec-00003-FR-6)
  Given 恰一个会话处于等待输入标记中
  When 该会话结束（自然退出或终止）
  Then 标记解除、计数归零且徽标不再呈现
- **spec-00003-AC-6.4** (spec-00003-FR-6)
  Given 一个会话进程已退出、收尾尚在进行
  When 其无输出时长达到静默阈值
  Then 不判定为等待输入，徽标计数不变
- **spec-00003-AC-6.5** (spec-00003-FR-6)
  Given 两个会话都处于等待输入
  When 查看顶栏与会话面板
  Then 等待计数为 2，两项均呈等待输入态
- **spec-00003-AC-6.6** (spec-00003-FR-6)
  Given 一个运行中会话正在持续产出、未达静默阈值
  When 其输出流中出现 OSC 777 通知序列
  Then 立即置位等待输入并锁存，不待静默阈值
- **spec-00003-AC-6.7** (spec-00003-FR-6)
  Given 一个会话已经信号通路锁存等待输入
  When 该会话继续产出输出（如状态栏重绘或插件行）
  Then 标志保持置位，等待计数不变
- **spec-00003-AC-6.8** (spec-00003-FR-6)
  Given 一个会话已经信号通路锁存等待输入
  When 用户在其终端按下任一按键（未提交）
  Then 标志解除、计数随之减少，静默通路重新武装
- **spec-00003-AC-6.9** (spec-00003-FR-6)
  Given 一个会话已经信号通路锁存等待输入
  When 该会话结束（自然退出或终止）
  Then 标志解除，计数随之减少，徽标沿零态口径
- **spec-00003-AC-6.10** (spec-00003-FR-6)
  Given 一个会话进程已退出、收尾尚在进行
  When 其残余输出中出现 OSC 777 通知序列
  Then 不置位等待输入，徽标计数不变（沿 AC-6.4 口径）
- **spec-00003-AC-6.11** (spec-00003-FR-6)
  Given 一个会话已由静默通路置位等待输入、未锁存
  When 其输出流中出现 OSC 777 通知序列
  Then 等待输入保持置位并转入锁存，等待计数不变（该输出块不触发解除）
- **spec-00003-AC-6.12** (spec-00003-FR-6)
  Given 一个会话已经信号通路锁存等待输入
  When 其输出流中再次出现 OSC 777 通知序列
  Then 状态与计数不变（重复信号幂等）
- **spec-00003-AC-6.13** (spec-00003-FR-6)
  Given 一个运行中会话
  When OSC 777 序列被拆成两个输出块相继到达
  Then 仍置位等待输入并锁存
- **spec-00003-AC-7.1** (spec-00003-FR-7)
  Given 一个会话运行中且终端面板正呈现另一个会话
  When 该会话自然结束
  Then 提示条通知呈现其会话种类、目标文档 id 与结束态，面板中该项转入已结束
- **spec-00003-AC-7.2** (spec-00003-FR-7)
  Given 一个会话运行中
  When 用户终止它
  Then 同样得到提示条通知，结束态为终止，收尾恰执行一次
- **spec-00003-AC-7.4** (spec-00003-FR-7)
  Given 所选 agent CLI 不存在
  When 发起会话、启动失败
  Then 得到提示条通知且结束态为失败（终端错误呈现照 `spec-00001-FR-16`）
- **spec-00003-AC-7.3** (spec-00003-FR-7)
  Given 两个会话运行中
  When 两者几乎同时结束
  Then 各得到一条提示条，逐条堆叠、互不合并
- **spec-00003-AC-8.1** (spec-00003-FR-8)
  Given 两个会话各自修改了不同的文档
  When 两者相继结束，且后结束者的写入发生在先结束者收尾之后
  Then 产生两个 commit，各自的暂存集只含自己修改的文件，commit 信息各指明
   自己的动作种类与文档 id
- **spec-00003-AC-8.2** (spec-00003-FR-8)
  Given 两个会话中只有一个产生了 `docs/` 变更
  When 两者相继结束，且产生变更的会话先结束
  Then 恰产生一个 commit——由产生变更的会话产生，另一会话不产生 commit
- **spec-00003-AC-8.3** (spec-00003-FR-8)
  Given 用户已选中某节点，两个会话运行中
  When 两者几乎同时结束
  Then 白板呈现两次收尾后的最新图，当前选中保持，同批刷新合并为一次
- **spec-00003-AC-8.4** (spec-00003-FR-8)
  Given 一个会话正在收尾
  When 用户同时保存一次编辑
  Then 产生互不吞并的两个 commit，各自暂存集只含各自的变更
- **spec-00003-AC-8.5** (spec-00003-FR-8)
  Given 两个会话都修改了同一份第三方文档
  When 两者相继结束
  Then 全部变更均被提交、无丢失；归属按结束顺序，先结束者的 commit 允许
   含对方对该文件的变更（已知噪音）
- **spec-00003-AC-8.6** (spec-00003-FR-8)
  Given 两个会话各自修改了不同的文档，且写入都发生在对方收尾之前
  When 两者在同一批次相继结束
  Then 全部变更均被提交、`docs/` 无遗留脏文件，至多产生两个 commit；
   后结束者收尾时无残余则不产生 commit（归属按结束顺序）
- **spec-00003-AC-9.1** (spec-00003-FR-9)
  Given 两个会话运行中
  When 浏览器断开后重新打开白板
  Then 会话面板列出这两个会话，各自终端含此前输出且可继续交互
- **spec-00003-AC-9.2** (spec-00003-FR-9)
  Given 一个会话运行中且浏览器已断开
  When 该会话在断开期间结束、之后重新打开白板
  Then 该会话呈现为已结束，其 commit 与历史落盘已照常完成
- **spec-00003-AC-9.3** (spec-00003-FR-9)
  Given 一个会话运行中
  When 服务端正常关停后重新启动，重新打开白板
  Then 该会话已按终止收尾（commit 与历史落盘），面板呈现空态，其转写可在
   会话历史中查到
- **spec-00003-AC-10.1** (spec-00003-FR-10)
  Given 一份文档的会话运行中
  When 查看顶层白板
  Then 该文档节点带运行中标记，激活标记即在终端面板呈现该会话
- **spec-00003-AC-10.2** (spec-00003-FR-10)
  Given 一份文档的会话处于等待输入
  When 查看顶层白板
  Then 该节点的标记呈等待输入态，与运行中标记以非颜色手段可区分
- **spec-00003-AC-10.3** (spec-00003-FR-10)
  Given 一份文档的会话已结束
  When 白板随会话结束刷新
  Then 该节点不再带会话状态标记
- **spec-00003-AC-10.4** (spec-00003-FR-10)
  Given 一份文档的会话运行中
  When 查看图与顶栏诊断计数
  Then 图中无新增关系边，诊断计数不因标记而变化

## 6. Out of Scope

- 邮件等其他板外通道——仍范围外（原「板外通知」条目的桌面通知半边已由
  [spec-00004](spec-00004-whiteboard-desktop-notifications.md) 接管，
  decision-00010 推翻了 `decision-00009` §2 第 8 条对其的维持；本条即
  第十七轮修订轮对原条目的改写）
- 跨服务重启的会话存续（tmux 式 PTY 托管，`decision-00009` §3 否决）
- 多用户 / 多浏览器并发协作（仍是本地单人白板）
- 历史会话的检索与管理增强（`spec-00001-FR-54` 现状不变）
- 同屏并排呈现多个终端（一次呈现一个）
- 静默阈值的用户配置（实现常数，`decision-00009` §3 否决）
- OSC 777 通知序列标题与正文的语义解析（措辞随 CLI 版本变，只识别序列
  本身，`decision-00011` §3 否决）
- OSC 9 等其他终端通知约定的识别（未经实测，待有实证再议，
  `decision-00011` §3）
- 以信号通路取代静默通路（实测信号迟于静默阈值约 44s 且非 claude CLI
  不发，`decision-00011` §3 否决）

## 7. Non-Functional

- 每个会话一个本地 CLI 进程；上限（FR-3）即资源上界，白板不做进程级配额。
