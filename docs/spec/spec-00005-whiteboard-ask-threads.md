# Spec: 答疑线程——问完即走的只读问答，终端答疑退役

> 在节点浮窗或编辑器提问，agent 以 headless 调用在后台作答；每个问题
> 是一个独立会话（答疑线程），追问接续该问的会话；一个文档的线程积累
> 成问题列表，作为编辑器的第三视图态（与编辑、预览并列）可浏览。答疑
> 只读、不占文档、不产生 commit；回答送达走既有桌面通知。终端形态的
> 答疑（`spec-00001-FR-47`）退役。路线与全部取舍见 decision-00012，
> 全部裁决经域主逐条确认。

- 本 spec 新增术语（拟，接收后进 `CONTEXT.md`）：
  - **答疑线程（Ask Thread）**：一个问题及其追问链——每个新问题开
    一个独立的 agent 会话，追问接续该会话；只读，落盘板外。
    _Avoid_：聊天、评论、对话（宽泛）
  - **问题列表（Ask List）**：一个文档积累的全部答疑线程，作为其
    编辑器的第三视图态（与编辑、预览并列）逐项呈问题与状态、点开
    呈现该项问答，可浏览。
    _Avoid_：问答历史（会话历史是另一词条）、消息列表
  - **headless 调用（Headless Call）**：agent CLI 的非交互一次性
    调用：给定问题、打印回答、进程退出；无 PTY、无终端，靠会话接续
    标识使追问共享同一上下文。
    _Avoid_：API 调用（仍是本地 CLI）、后台会话（会话是注册表的词）

## 4. System Requirements

- **spec-00005-FR-1** (Event) 当用户对任意类型、任意状态的正常文档
  节点执行答疑时——入口有二：节点浮窗（保留原入口、形态改变）与该
  文档编辑器内的提问入口（新增）——系统应提供问题输入（不再出现
  终端），并以问题文本发起一条新答疑线程的首调：指令含目标文档路径
  与其全部关系文档路径（沿用原 `spec-00001-FR-47` 的上下文口径）、
  只读答疑的性质说明（回答问题，不修改任何文件），问题文本作为第一
  问附于其后。
- **spec-00005-FR-2** (Ubiquitous) 每个新问题应开一条独立的答疑线程
  （独立 agent 会话），成为该文档问题列表的一项；线程记录问题、
  回答、提交与回答时刻、所用 agent；追问以线程持有的接续标识接续
  **该线程**的会话，指令只含追问文本（FR-1 的路径与性质说明不重发，
  上下文不重付）；接续只对原 CLI 有效，追问因此沿用该线程的 agent；
  新线程的 agent 选择沿用 `spec-00001-FR-55` 口径，可选集收窄为已
  声明 headless 形态的 agent。
- **spec-00005-FR-3** (Complex) 当一次调用提交后，系统应允许输入
  界面立即收起，且不呈现终端面板——答疑会话永不被终端面板呈现，
  也不作为终端无呈现时的回落对象（`spec-00003-AC-5.4` 的首会话自动
  呈现对答疑不触发；回落不取答疑是本条自己的条款）。进行中状态在
  问题列表项上呈现，节点标记
  与激活行为见 FR-9；页面刷新后按注册表列表恢复（`spec-00003-FR-4`）。
  当调用以零退出结束且捕获到输出时（已回答的唯一判定），该线程呈
  已回答，回答经控制序列剥离后按 Markdown 渲染（复用既有预览渲染）；
  调用结束照常出结束提示条（`spec-00003-FR-7`，其 commit 收尾半句
  对答疑不适用）。线程只增不删（清空入口见 §6）。
- **spec-00005-FR-4** (Ubiquitous) 答疑的 headless 调用应以所选 CLI
  的只读约束形态发起：只读旗标集是 headless 声明（FR-8）的一部分
  （逐 CLI 而异，claude 的缺省声明随 design-00001 修订轮给出）；
  越界写入由 CLI 的权限机制拒绝，白板不做 git 回滚兜底（同
  `spec-00001-FR-13` 的既有口径）。该形态不作会话前快照、完全排除
  于 commit 归属通路之外（`spec-00003-FR-8` 不适用）：调用结束不
  产生任何 commit，仓库残余归写它的会话。答疑不改变文档 status
  （per `rule-00001-BR-21`）。
- **spec-00005-FR-5** (Complex) 问题列表应按文档 id 键控、持久于板
  外存储（与会话转写同侧，不入 git、不进 `docs/`；位置与文件形态属
  design）；文档删除或改 id 后列表不再呈现、存储保留（§6）。服务
  重启后列表与各项问答可见；追问接续原会话为尽力而为——接续标识的
  跨重启有效性由该 CLI 决定，被拒绝的接续按 FR-7 的失败分支处置。
  正常关停时运行中的调用走既有终止收尾（`spec-00003-FR-9`），线程
  记终止态、可重发；服务异常终止遗留的进行中问题，启动时核销为失败
  态、可重发。每次调用的会话历史条目照写（`spec-00001-FR-54`）：
  元数据加捕获的回答文本充当转写。
- **spec-00005-FR-6** (Complex) 答疑调用应计入会话注册表（kind 为
  答疑）：总并发上限适用（`spec-00003-FR-3`），会话面板照常列出
  （`spec-00003-FR-4`，点击导航见 FR-9）；但**不占目标文档**——
  `spec-00003-FR-2` 的文档占用及 `spec-00003-FR-1`/
  `spec-00001-FR-18` 的对应前件与拒绝面对答疑 kind 排除：同文档的
  答疑与推进/澄清/审计互不阻塞，同文档多条线程可并行作答（各自独立
  会话）。答疑 kind 应排除于等待判定的两条通路之外
  （`spec-00003-FR-6` 交接，`spec-00004-FR-2` 随之派生不适用）：
  静默不置位等待输入、不出徽标、不出等待通知。调用结束经既有通路
  通知（`spec-00004-FR-3`，离场时送达），通知内容口径不变
  （`spec-00004-FR-6`；同文档多线程的通知同题不可分辨——已知边界，
  §6）。
- **spec-00005-FR-7** (Unwanted) 若一条线程已有进行中的调用（首调或
  追问），该线程的再次提交应被拒绝且不发起调用（追问天然串行）；
  异常节点不提供答疑入口——浮窗无该入口、其编辑器不呈现提问入口、
  经接口直接请求被拒绝（沿用原 `spec-00001-FR-47` 口径）；无任何
  agent 声明 headless 形态时两处入口均不呈现，经接口请求被拒绝；
  调用以非零退出结束、或 CLI 拒绝接续标识时，该问记为失败态、列表
  既有问答不受影响，问题可重发（重发开新调用）；运行中的调用经会话
  面板**逐项终止入口**（新增——答疑无终端面板可依，终端形态会话的
  终止入口位置不变）可终止（`spec-00001-FR-49`）：进程结束、该问记
  终止态、可重发；系统不以无输出时长判定失败（无超时——手动终止
  兜底）；经接口对答疑会话请求终端接入、输入或尺寸调整应被拒绝。
- **spec-00005-FR-8** (Ubiquitous) 流程配置的 agent 条目应可携带
  可选的 headless 声明：首调与接续两种命令形态、问题占位与只读旗标
  （接续标识的捕获口径属 design）；声明不合式时按 `spec-00001-FR-15`
  启动校验拒绝并点名该条目；未声明的 agent 不进入答疑的可选集
  （FR-2），全部未声明的拒绝面由 FR-7 承接。
- **spec-00005-FR-9** (Complex) 问题列表应作为文档编辑器的第三视图
  态呈现（与编辑、预览并列），槽位规则不变（`spec-00001-FR-31` 原样
  适用——列表随编辑器占用右侧槽位）：逐项呈问题与状态，点开一项
  呈现其全部问答并可追问。浮窗答疑入口、会话面板项点击与桌面通知
  点击应打开该文档的编辑器并切到问题列表态、定位该线程，既有编辑
  缓冲保留（视图态切换不丢缓冲，同编辑/预览切换口径）；就近处置与
  `spec-00004-FR-5` 同构：会话已不在本次服务运行的列表中时提示且不
  改变当前视图；目标文档不在图上时同样提示且不导航——列表视图寄居
  编辑器，无节点即无编辑器（保守选择，列表存储仍在，FR-5）。节点
  会话标记（`spec-00003-FR-10`）：文档有一个及以上运行中会话即呈现
  一个标记（不逐会话计数）；激活标记时，存在终端形态会话则在终端
  面板呈现它（`spec-00003-FR-2` 对非答疑 kind 仍互斥，同文档至多
  一个终端形态会话），否则切到该文档的问题列表态。

**Acceptance (GWT)**

- **spec-00005-AC-1.1** (spec-00005-FR-1)
  Given 一个 `active` 文档的编辑器已打开
  When 用户经编辑器的提问入口提交问题
  Then 发起一次 headless 首调，指令依次含目标文档路径、全部关系文档
  路径、只读性质说明与该问题文本，不出现终端
- **spec-00005-AC-1.2** (spec-00005-FR-1)
  Given 一个与两份文档互有引用的节点
  When 从其浮窗执行答疑并提交问题
  Then 同一问题输入与首调发起，指令包含那两份关系文档的路径
- **spec-00005-AC-1.3** (spec-00005-FR-1)
  Given 一个 `active` 的 record 节点
  When 执行答疑并提交问题
  Then 首调照常发起——答疑不限类型与状态（承接原
  `spec-00001-AC-47.1`）
- **spec-00005-AC-2.1** (spec-00005-FR-2)
  Given 一条线程已有一问一答
  When 用户在该线程追问
  Then 调用携带接续标识接续同一 agent 会话，指令只含追问文本，线程
  追加第二组问答，各组带提交与回答时刻及所用 agent
- **spec-00005-AC-2.2** (spec-00005-FR-2)
  Given 一个文档已有一条已回答的线程
  When 用户提交一个新问题
  Then 问题列表出现第二条线程，其首调不携带接续标识（独立会话）
- **spec-00005-AC-2.3** (spec-00005-FR-2)
  Given 流程配置两条 agent，仅其一声明 headless 形态
  When 用户执行答疑
  Then agent 可选集只含声明者；新线程可另选 agent，追问沿用该线程的
  agent
- **spec-00005-AC-3.1** (spec-00005-FR-3)
  Given 一次调用已提交、输入界面已收起
  When 调用以零退出结束且捕获到含控制序列的输出
  Then 该线程呈已回答，回答已剥离控制序列并按 Markdown 渲染，结束
  提示条照常出现且无 commit 收尾
- **spec-00005-AC-3.2** (spec-00005-FR-3)
  Given 一次调用进行中
  When 用户查看该文档的问题列表
  Then 该线程呈进行中
- **spec-00005-AC-3.3** (spec-00005-FR-3)
  Given 一次调用进行中
  When 页面刷新
  Then 进行中状态按注册表列表恢复呈现
- **spec-00005-AC-3.4** (spec-00005-FR-3)
  Given 无任何会话且终端面板未呈现
  When 提交一个问题
  Then 终端面板不呈现（对比 `spec-00003-AC-5.4` 的首会话自动呈现）
- **spec-00005-AC-3.5** (spec-00005-FR-3)
  Given 一次答疑调用是最近启动的会话、另有一个更早的推进会话运行中
  When 页面重连且终端面板无呈现对象
  Then 终端回落呈现推进会话——答疑永不被终端呈现
- **spec-00005-AC-4.1** (spec-00005-FR-4)
  Given 一个 `draft` 文档的一条线程
  When 一次调用完成
  Then 该文档 status 仍为 `draft`，无任何 commit 产生
- **spec-00005-AC-4.2** (spec-00005-FR-4)
  Given 所选 agent 的 headless 声明含其只读旗标
  When 一次答疑调用发起
  Then 实际执行的命令行含该只读旗标——约束到调用形态，不靠 agent
  自觉
- **spec-00005-AC-4.3** (spec-00005-FR-4)
  Given 另一文档的推进会话已写入 `docs/`
  When 本文档的答疑调用先结束
  Then 不产生任何 commit，残余仍归推进会话按 `spec-00003-FR-8` 处置
- **spec-00005-AC-5.1** (spec-00005-FR-5)
  Given 一个文档的问题列表已有问答
  When 服务重启后打开该列表并在一条线程追问
  Then 既有问答可见，追问携带原接续标识发起
- **spec-00005-AC-5.2** (spec-00005-FR-5)
  Given 问题列表存储所在目录
  When 检查版本库
  Then 列表文件不被 git 跟踪，`docs/` 下无问答内容
- **spec-00005-AC-5.3** (spec-00005-FR-5)
  Given 一次调用进行中时服务异常终止（未走正常关停）
  When 服务重启后打开该文档的问题列表
  Then 该问呈失败态且可重发，不呈永久进行中
- **spec-00005-AC-5.4** (spec-00005-FR-5)
  Given 一次调用进行中
  When 服务正常关停
  Then 该调用走终止收尾，重启后该问呈终止态且可重发
- **spec-00005-AC-5.5** (spec-00005-FR-5)
  Given 一次调用以零退出结束
  When 查看会话历史
  Then 该调用有历史条目，含元数据与捕获的回答文本
- **spec-00005-AC-6.1** (spec-00005-FR-6)
  Given 一个文档的推进会话运行中
  When 对该文档提交答疑
  Then 调用照常发起——不因文档占用被拒（改写原 `spec-00001-AC-18.1`
  对此方向的断言）
- **spec-00005-AC-6.2** (spec-00005-FR-6)
  Given 一个文档的答疑调用进行中
  When 对该文档发起推进
  Then 推进照常启动——答疑不占用文档
- **spec-00005-AC-6.3** (spec-00005-FR-6)
  Given 一个文档已有一条进行中的线程
  When 提交另一个新问题
  Then 第二条线程照常发起，两次调用并行运行（各自独立会话）
- **spec-00005-AC-6.4** (spec-00005-FR-6)
  Given 总并发已达上限（`spec-00003-FR-3`）
  When 提交一次答疑调用
  Then 被拒且列表不追加
- **spec-00005-AC-6.5** (spec-00005-FR-6)
  Given 一次答疑调用连续无输出超过静默阈值且进程存活
  When 查看该会话
  Then 不呈现等待输入——无徽标、无等待通知、面板行无等待态
- **spec-00005-AC-6.6** (spec-00005-FR-6)
  Given 桌面通知开关生效且页面离场（`spec-00004-FR-3` 前提）
  When 一次答疑调用结束
  Then 弹结束通知，内容只含种类、文档 id 与状态
- **spec-00005-AC-7.1** (spec-00005-FR-7)
  Given 一条线程已有进行中的调用
  When 在该线程再次提交（追问或重发）
  Then 被拒绝且不发起第二次调用
- **spec-00005-AC-7.2** (spec-00005-FR-7)
  Given 一个异常节点对应的文档
  When 经接口请求答疑
  Then 被拒绝且不发起调用
- **spec-00005-AC-7.3** (spec-00005-FR-7)
  Given 一个异常文档（其编辑器仍可达，`spec-00001-FR-2`）
  When 打开其编辑器
  Then 编辑器不呈现提问入口
- **spec-00005-AC-7.4** (spec-00005-FR-7)
  Given 全部 agent 均未声明 headless 形态
  When 打开正常节点的浮窗与编辑器
  Then 均不呈现答疑入口；经接口请求被拒绝
- **spec-00005-AC-7.5** (spec-00005-FR-7)
  Given 一次调用以非零退出结束
  When 查看该线程并重发该问
  Then 该问此前呈失败态、列表既有问答完好，重发发起新调用
- **spec-00005-AC-7.6** (spec-00005-FR-7)
  Given 一次答疑调用进行中
  When 用户经会话面板该项的终止入口终止它
  Then 进程结束，该问呈终止态且可重发
- **spec-00005-AC-7.7** (spec-00005-FR-7)
  Given 一次答疑调用进行中
  When 经接口对其请求终端接入、输入或尺寸调整
  Then 三者均被拒绝
- **spec-00005-AC-8.1** (spec-00005-FR-8)
  Given 一条 agent 配置的 headless 声明缺少必需占位
  When 服务启动
  Then 启动被拒且报错点名该 agent 条目（`spec-00001-FR-15` 口径）
- **spec-00005-AC-8.2** (spec-00005-FR-8)
  Given 一条 agent 配置携带合式的 headless 声明
  When 一条线程首调与追问相继执行
  Then 两次调用各按声明的首调与接续命令形态执行
- **spec-00005-AC-9.1** (spec-00005-FR-9)
  Given 一个文档有三条线程：已回答、进行中、失败
  When 打开其编辑器并切到问题列表态
  Then 逐项呈问题与对应状态，点开已回答项可见其全部问答并可追问
- **spec-00005-AC-9.2** (spec-00005-FR-9)
  Given 该文档编辑器打开在编辑态且缓冲有未保存修改
  When 用户点击该文档一条答疑调用的桌面通知
  Then 编辑器切到问题列表态并定位该线程，未保存缓冲保留
- **spec-00005-AC-9.3** (spec-00005-FR-9)
  Given 一次答疑调用进行中或已结束
  When 在会话面板点击该项
  Then 打开该文档编辑器的问题列表态并定位该线程
- **spec-00005-AC-9.4** (spec-00005-FR-9)
  Given 一条答疑调用的结束通知已弹出、其目标文档已不在图上
  When 用户点击该通知
  Then 提示目标不在图上，当前视图不变（列表存储仍在）
- **spec-00005-AC-9.5** (spec-00005-FR-9)
  Given 一条答疑调用的通知已弹出、其会话已随服务重启不在列表中
  When 用户点击该通知
  Then 提示该会话已不在，当前视图不变
- **spec-00005-AC-9.6** (spec-00005-FR-9)
  Given 同一文档一条答疑调用与一个推进会话并行运行
  When 查看该节点并激活其会话标记
  Then 节点只呈现一个标记，激活后终端面板呈现推进会话
- **spec-00005-AC-9.7** (spec-00005-FR-9)
  Given 一个文档仅有答疑调用运行中
  When 激活其节点会话标记
  Then 打开该文档编辑器的问题列表态——不呈现终端

## 6. Out of Scope

- 答疑修订文档的任何能力（只读是站立约束，`decision-00012` §5；修订
  走编辑器、推进或澄清）
- 线程与列表的清空/删除入口（只增不删，FR-3；清空留将来轮）；文档
  删除或改 id 后遗留的列表存储（不呈现、保留，FR-5——回收留将来轮）
- 无输出超时判败（FR-7 明文不做——手动终止兜底）
- 同文档多条线程的桌面通知与提示条同题不可分辨（`spec-00004-FR-6`
  内容口径不动，路由靠会话标识——已知边界，宁简勿改）
- 问答内容的搜索、导出、跨文档汇总，及线程长度/回答体量的配额
- 多用户/多浏览器对同一列表的并发追问协调（单人工具的既有前提）
- 跨服务重启的进行中调用存续（`spec-00003-FR-9` 口径；FR-5 承诺的
  是正常关停记终止、异常终止核销失败）
- 推进/澄清/审计三种会话的任何改动（终端通道原样保留）

## 7. Open Questions

无——本轮裁决闭合：形态统一与双入口、无等待只有结束通知、问题附于
既有指令后、按问追问（resume）、只读不锁、问题并行/追问串行，经域主
逐条确认（在案于 `decision-00012`）；两轮审计揭出的四个新状态（多
会话节点标记、无终端的终止入口、列表的槽位归属、关停与崩溃的线程
终态）已在 FR-5/FR-7/FR-9 落成条文；claude 缺省 headless 声明的具体
旗标集与接续标识捕获口径委给 design-00001 修订轮（§5）。
