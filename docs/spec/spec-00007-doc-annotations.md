# Spec: 文内标注——选区上的 question 与 issue，攒批提交与进展追踪

> 在编辑器的编辑与预览两种视图态里选中文本、右键加标注：question 要
> 回答，issue 要修改。标注锚定选区内容（不锚行号）并携带原文引用；
> 一份文档攒多条，一键统一提交——question 各开答疑线程，issue 作为
> 材料合入**一个共写会话**（复用既有共写，不新立会话种类）；标注
> 列表逐条追进展。取舍在案于 `idea-00003` 与 `prd-00002` 的已定
> 方向，经域主逐条确认；审计轮的四项裁决（复用共写、提交前须无
> 未保存改动、类型不守门、总并发上限适用）见 §7。

## 1. Context

- canonical terms 见 `CONTEXT.md`：标注、选区锚、孤儿标注、标注列表、
  答疑、答疑线程、问题列表、headless 调用、共写、修订轮、状态流转、
  评审动作、接收、审计、Agent 会话、会话面板、等待输入、终止、桌面
  通知、会话历史、会话前快照、留痕、预览、呈现状态、异常。
- 输入：`parent` 为 [prd-00002-doc-annotations](../prd/prd-00002-doc-annotations.md)
  （其九条功能需求全部由本 spec 承载）；上游裁决见
  [idea-00003-doc-annotations](../idea/idea-00003-doc-annotations.md)
  已定方向十五条（第 6、7 条随审计轮据实校正为共写承载）。
- 本 spec 是既有白板 spec 族的**并列新 spec**（Sizing and Splitting
  第 1 条），不 supersede 任何一份；`parent` 挂 `prd-00002`（标注是
  独立立项的能力）。
- **不新立会话种类**：issue 通路复用共写会话（`spec-00006` /
  `decision-00015`）——共写立项时把「没有修订会话」列为现状缺口并
  以共写填补（`decision-00015` §1 缺口清单、§2 第 1 条），本 spec
  与其同向：标注提交只是共写的一个新发起来源与材料构成方式，注册
  表、互斥、上限、等待、通知、快照、收束过滤、收束 commit、运行期
  状态锁全部原样适用，`spec-00001`/`spec-00003`/`spec-00004` 的
  会话**种类**枚举零改动（入口禁用两处半句的排除见交接清单）。
  连带效应：「会话只修订目标文档（与合式新建 `reference`）」由共写
  写域（`rule-00001-BR-30`、`spec-00006-FR-6` 收束过滤）**机制性**
  保证，不再是指令纪律。
- **与既有文档的交接**（本清单是交接的完整口径，不就地改各文档——
  改写属各自的修订轮，plan 登记）：
  - `spec-00005-FR-1`（答疑入口枚举，现为节点浮窗与编辑器提问入口
    两处）：增第三来源「标注统一提交的 question 通路」，其首调指令
    在既有口径后附选区材料（FR-6）——属其修订轮。
  - `spec-00005-FR-9`（问题列表导航来源枚举，现为会话面板项点击与
    桌面通知点击两处）：增第三来源「标注列表 question 项点击」
    （FR-9）——属其修订轮。
  - `spec-00006-FR-1`（共写发起）与 `spec-00006-FR-3`（材料输入）：
    发起来源增「标注统一提交」——触发主体是提交动作而非用户对节点
    的直接动作，材料段由系统按 FR-7 程序化构成（用户不经材料输入
    UI）——属其修订轮。
  - `spec-00006-FR-4` 的「发起成功时编辑器以 Source 视图打开目标
    文档」的一次覆盖对标注来源**不适用**：统一提交发生在该文档的
    编辑器语境内，保持用户当前呈现（终端与运行期其余语义——同屏、
    缓冲重载、非等待期只读——照常）——属其修订轮。
  - `spec-00003-FR-2` 与 `spec-00003-FR-3` 的「发起入口禁用」半句
    对统一提交入口**排除**：提交入口不随同文档互斥或总并发上限
    整体禁用——其拒绝按 FR-10 在提交时逐通路判定（issue 拦下、
    question 照常），同 `spec-00005-FR-6` 为答疑登记排除的先例——
    属其修订轮。
  - `rule-00001-BR-28`（共写定义与材料给法枚举）：材料给法增「标注
    统一提交程序化构成的选区材料」；「材料不构成会话间记忆」照旧
    成立——终止/失败后再提交发起的新会话各自重新拿到材料——属其
    修订轮。其余零改动：issue 发起资格完全由既有 BR-2…BR-9（流转
    表）与 BR-29（共写资格）承载，自动流转走 BR-3 的合法路径，
    「不是评审动作、不改变状态」是共写的既有属性，写域是 BR-30。
  - `prd-00001` 修订轮：能力清单加一行指针指向 `prd-00002`（标注
    能力属独立 PRD，避免两清单漂移）。
  - `CONTEXT.md` 随本 spec 接收修订：「标注」词条的「spec 待立」
    改为由本 spec 持有，其 issue 半句「触发修订轮」细化为「转回
    `draft` 并发起共写」；「选区锚」词条补恰一处命中口径（上下文
    参与消歧）；「孤儿标注」词条的「锚文本被改或删」补歧义命中；
    「呈现状态」为封闭枚举——标注呈现所落的视图态与定位项待
    design 修订轮定形后随之入列（见 FR-9，呈现归属属 design）。
- 本 spec 不新增术语——「修订会话」是共写词条的待避词，不使用；
  issue 批的进展状态用「共写中」等普通词，见 FR-9。
- 规模：本 spec 12 FR / 70 AC，正文约 620 行——已越过 Sizing 的
  「~500 正文行」触发线，刻意不拆：标注是一个连贯增量（加注、
  提交、双通路、进展是一条链），拆开任何一半都不可独立交付；FR 数
  （12）远低于 ~20 的触发线，行数主要来自逐条 GWT。

## 4. System Requirements

- **spec-00007-FR-1** (Event) 当用户在一份正常文档编辑器的编辑或预览
  视图态中选中一段非空文本并执行添加标注时，系统应提供类型选择
  （question / issue，可选集由 FR-4、FR-10 守门）与标注文本输入；
  确认后记录一条未提交标注：类型、标注文本、选区锚（选区文本及其
  上下文）、选区原文引用、创建时刻。预览视图态中的选区应落为**源
  文本**上的选区锚（渲染文本到 Markdown 源的映射属 design）；编辑
  视图态中对未保存缓冲文本的选区照常可标注（锚对缓冲文本成立；
  提交须先保存，FR-5）。无选区时不提供添加标注入口；标注文本为空
  的确认应被拒绝、不记录。
- **spec-00007-FR-2** (Ubiquitous) 选区锚应锚定内容而非行号：锚文本
  之外的任何文档改动（增删段落、移动章节）不影响定位。命中判定以
  锚的**整体**（选区文本及其上下文）为键——上下文参与消歧，选区
  文本是常见短语时通常仍可唯一定位。定位成功要求**恰一处命中**：
  键被改动或删除（零命中）与键在文中多处等同命中（歧义命中，含
  整段重复文本使创建时刻即歧义的罕见情形）均为定位失败——提交前
  的失败由 FR-5 拦下，提交后的失败按 FR-12 退化（判定细则属
  design，恰一处命中是条文级口径）。选区原文引用是独立于锚有效性
  的兜底：锚失效后引用照常可见、可用。
- **spec-00007-FR-3** (Ubiquitous) 未提交标注应按文档 id 键控、持久
  于板外存储（与问题列表同侧：不入 git、不进 `docs/`，位置与文件
  形态属 design）；一份文档可积累多条；提交前每条可修改标注文本与
  类型（改为 issue 受 FR-4 的类型可选集同门）、可删除、可**重新
  选区**（重新选中一段文本，替换该条的选区锚与原文引用——孤儿
  标注的「重新选区」出路即此能力）；页面刷新与服务重启后未提交
  标注保留。
- **spec-00007-FR-4** (Unwanted) issue 的守门条件为：目标文档当前在
  `draft` 或 `open`（`rule-00001-BR-29` 可直接发起共写），或为
  `active` 的 living doc（可经 `rule-00001-BR-3` 合法转回 `draft`）；
  类型不设守门（任意类型皆可，同共写口径——域主裁定，§7）。条件
  不满足（work item 的 `resolved`/`wontfix`、两种类的 `archived`）
  时，添加标注的类型可选集不含 issue（question 照常），经接口添加
  issue 类型标注应被拒绝。守门在提交时**复验**：标注攒下后文档因
  流转丧失资格的，统一提交的 issue 部分应整体拦下、原因指明资格，
  question 部分照常。异常文档不提供任何标注入口（编辑器不呈现添加
  入口，经接口添加或提交被拒绝——同答疑的异常口径）。
- **spec-00007-FR-5** (Event) 当用户对一份文档执行统一提交时：编辑
  缓冲有未保存改动的，提交应**整体**被拒绝并提示先保存（无任何
  通路发起——该前置先于 FR-10 的逐通路判定；目标文档正处共写非
  等待期、保存被 `spec-00006-FR-4` 只读禁用时，出路是等待期或会话
  结束后保存再提交）；无未提交标注时统一提交入口不可用，经接口空
  提交应被拒绝。前置通过后，系统应逐条以**磁盘正文**重新定位选区
  锚（恰一处命中，FR-2）：定位失败的条目标为孤儿标注、单条拦下
  ——留在未提交区、标明失效并呈其原文引用，待重新选区（FR-3）或
  删除；其余条目分派两通路（question 见 FR-6，issue 见 FR-7），
  一条失效不阻整批。分派次序可观察：**先发起共写会话、后逐条发起
  question**（名额紧张时一个名额优先承载整批 issue）。agent 选择
  **逐通路**进行：question 通路与共写通路各按其可选集沿
  `spec-00001-FR-55` 口径（多于一条时呈现选择、未指定各取各可选集
  的第一条）——question 的可选集为已声明 headless 形态者
  （`spec-00005-FR-2`），共写的为全部 agent。提交入口应明示本次将
  发生的动作（发起答疑数、发起共写、目标将转 `draft`——呈现形态
  属 design）。
- **spec-00007-FR-6** (Event) 当统一提交含 question 标注时，每条
  question 应各发起一条新答疑线程的首调（`spec-00005` 全部语义
  适用：headless、只读、无 commit、不占文档、线程进问题列表）：
  指令为既有口径（目标文档路径、全部关系文档路径、只读性质说明）
  加该条的选区原文及上下文，标注文本作为问题附于其后；标注持有其
  线程引用，状态与回答随线程（FR-9）。发起受既有拒绝面约束——含
  总并发上限（`spec-00005-FR-6`/`spec-00003-FR-3`，域主确认「不占
  名额」仅指不占文档，§7）：被拒的 question 单条拦下留未提交区、
  原因指明，不阻其余条目。
- **spec-00007-FR-7** (Event) 当统一提交含 issue 标注时，全部 issue
  应作为材料合入**一个共写会话**（`spec-00006` 语义适用：FR-1
  的指令骨架与写域约束、FR-4 的同屏/缓冲重载/非等待期只读——其
  「发起成功时以 Source 视图打开」的一次覆盖除外，§1 交接、FR-5
  的手改与注记、FR-6 的收束过滤、FR-8 的收束 commit、FR-10 的运行
  期状态锁）：材料段由系统程序化构成——逐条 issue 的选区原文、
  上下文与标注文本；任务指令附加纪律——按条修订并逐条报告、意图
  拿不准的 issue 停下来问（等待输入）、连带修改关系文档的诉求只
  报告不代写（写域外，写入也会被收束过滤复原）、不做任何评审动作。
  目标文档为 `active` 的 living doc 时，系统先自动执行
  `active → draft` 的合法状态流转（`rule-00001-BR-3`，复用状态
  切换的既有通路与其一动作一 commit 语义），已在 `draft`/`open`
  则不流转。流转与会话启动应**全有或全无**：任何拒绝面（FR-4、
  FR-5、FR-10）命中或会话未能启动（含 `spec-00001-FR-16` 的 CLI
  启动失败）时不留下流转——不存在「已转 `draft` 而无会话」的落点
  （内部次序属 design，此为可观察承诺，同 `spec-00006-FR-2` 先例）。
  全有或全无的边界是**流转写盘**：拒绝面与会话启动失败的判定先于
  写盘（不留任何痕迹）；写盘之后的失败不回滚——流转 commit 失败
  按 `spec-00001-FR-20` 既有语义（文件保留、错误呈现），会话照常
  启动（文档已在盘上为 `draft`，可共写；同 `spec-00006-FR-2` 对
  建档 commit 失败的裁定）；写盘后若会话仍未能启动（复合角落），
  文件同样保留为 `draft`、错误呈现、issue 留未提交区——修复后
  再提交走不流转分支。
- **spec-00007-FR-8** (Ubiquitous) 标注提交发起的共写会话与手工发起
  的共写应无行为差别：注册表与会话面板、同文档互斥与文档占用、总
  并发上限、等待判定与通知、会话前快照、收束过滤与收束 commit、
  运行期对状态切换/评审动作/front matter 保存的拒绝
  （`spec-00006-FR-10`）、终止——一体适用；差别恰为三处：发起
  来源、材料构成、发起时不做 Source 视图的一次覆盖（均 §1 交接）。经确认的连带修改不在本会话落地（
  `rule-00001-BR-30`）：会话对连带诉求的报告留在会话转写，由人对
  关系文档另行处理（另行标注、编辑或共写）。会话不是评审动作、不
  改变文档状态；修订完成后的审计与接收照既有语义由人发起。
- **spec-00007-FR-9** (Complex) 标注列表应从该文档的编辑器可达——
  其呈现归属（与问题列表并列的新视图态，还是合并呈现）属 design
  （`CONTEXT.md` 标注列表词条的既定口径），本条只承诺可观察行为：
  无标注时呈空态且入口仍在；有标注时逐项呈类型、标注文本、原文
  引用、状态与进展。标注状态模型：**未提交**（可改可删；孤儿是其
  失效标记，不是独立状态）→ 提交后，question 项的状态**镜像其答疑
  线程**（进行中、已回答、失败、终止——失败/终止的重发走问题列表
  的既有线程能力，标注项跟随），issue 项为批状态——**共写中** →
  **已完成**（会话自然结束），或**终止**/**失败**（终止、启动后
  异常核销）→ 回到未提交（可改可删可再提交）。question 项**不限
  线程状态**点击导航到问题列表并定位该线程（`spec-00005-FR-9` 对
  任意线程可定位）；
  共写中的 issue 项点击在终端面板呈现该会话；已完成的 issue 项呈
  该次收束 commit 的引用，无落地变更时明示无变更
  （`spec-00006-FR-8` 的无 commit 分支）。锚可定位（恰一处命中）
  的项应可从列表定位到编辑/预览中的对应选区；未提交且锚可定位的
  标注应在编辑与预览中有可见痕迹（形态属 design）；已提交项锚定位
  失败时呈「原文已变更」提示（FR-12）。页面刷新与服务重启后列表按
  存储恢复；标注呈现与其定位项并入呈现状态的既有口径（刷新后按 id
  保持、所指不存在时就近关闭——枚举入列见 §1）；与编辑器其他呈现
  之间的切换不丢编辑缓冲（同既有视图态切换口径）。
- **spec-00007-FR-10** (Unwanted) 拒绝与失败面（FR-5 的整体前置
  先行——前置不过则无部分发起）：目标文档已有运行中终端形态会话
  （含本文档标注提交此前发起的共写会话——自指互斥）时，统一提交
  的 issue 部分应整体被拒（原因指明同文档互斥，标注留未提交区，
  会话结束后可再次提交），question 部分照常发起；总并发
  上限使共写会话无法启动时，issue 部分同样整体拦下；同一文档的
  统一提交在途（上一次提交的分派尚未完成）时，再次提交应被拒绝且
  不重复发起任何线程或会话；无 agent 声明 headless 形态时，添加
  标注的类型可选集不含 question（对称 FR-4），经接口添加或提交
  question 被拒绝（issue 不受影响）；提交时目标文档已在盘上删除或
  改 id 的，提交应整体被拒绝（标注存储保留，FR-11）。共写会话被
  终止的，该批 issue 记终止态并回到未提交区；服务异常终止遗留的
  共写中批次，启动时核销为失败态并回到未提交区（核销口径同
  `spec-00005-FR-5`）；回到未提交区的标注可修改、可删除、可再次
  提交（再提交发起新会话）。
- **spec-00007-FR-11** (Ubiquitous) 标注（未提交与已提交）与其进展
  应落盘板外、不入 git；标注存储的读写自身不产生任何 commit。
  issue 通路的 commit 恰为：自动流转的 commit（如有，FR-7）、共写
  收束的 commit（如有落地变更，`spec-00006-FR-8`——会话合式新建
  的 `reference` 同该 commit 落地，BR-30 写域照旧）与会话期间用户
  手改的既有管道 commit（`spec-00006-FR-5`）；question 通路无
  commit（`spec-00005-FR-4`）。文档删除或改 id 后其标注不再呈现、
  存储保留（回收留将来轮，同问题列表口径）。
- **spec-00007-FR-12** (Complex) 已提交标注的锚定位失败（含共写
  会话自身的修改所致，及歧义命中）不算标注失效：处理不中断、状态
  不变，标注列表该项呈「原文已变更」提示、原文引用照常可见；该
  退化对 question 与 issue 一体适用，对已完成/已回答的标注同样
  适用（回看时原文已面目全非仍可读到当初的引用）。

  Given 一份有标注的文档
  When 该文档改 id 后查看
  Then 其标注不再呈现于任何列表，板外存储文件保留
- **spec-00007-AC-11.4** (spec-00007-FR-11)
  Given 一份有已完成标注的文档
  When 该文档在盘上被删除
  Then 其标注不再呈现，存储保留
- **spec-00007-AC-12.1** (spec-00007-FR-12)
  Given 两条 issue 一批共写中，会话修改 issue A 的段落时恰好改掉了
  issue B 的锚文本
  When 查看标注列表
  Then issue B 状态不变、处理不中断，其列表项呈「原文已变更」且
  原文引用可见
- **spec-00007-AC-12.2** (spec-00007-FR-12)
  Given 一条已回答的 question 标注，其锚文本其后被手工编辑删除
  When 查看该标注
  Then 线程与回答照常可见，定位退化为「原文已变更」提示
- **spec-00007-AC-12.3** (spec-00007-FR-12)
  Given 一条已完成的 issue 标注，其锚文本随后续修订轮被改写
  When 查看该标注
  Then 已完成态与收束 commit 引用照常可见，定位退化为「原文已
  变更」提示

## 6. Out of Scope

- comment 类型（idea 阶段裁掉）；标注的回复/讨论串（question 的追问
  走答疑线程既有能力）
- 编辑期间的实时重锚（锚校验只在统一提交时做，`idea-00003` 已定
  方向 9）
- issue 的逐条完成粒度（批状态随共写会话生命周期；逐条的修改内容
  见会话转写与收束 commit diff，结构化的逐条回执留将来轮——
  `prd-00002` 功能需求 8 的「所做修改」由收束 commit 引用与转写
  承载，属点名的部分承载）
- 攒批 question 的桌面通知同题不可分辨（`spec-00005` §6 的既有已知
  边界；一批 N 条 question 产出 N 条通知，暴露面随攒批放大——宁简
  勿改，路由靠会话标识照旧）
- 部分提交（选择性提交某几条）——统一提交是全量的，改删在提交前做
- 已提交标注的删除/清空与板外存储回收、标注条数与文本长度的配额
  （同问题列表「只增不删、无配额」的既有先例，`spec-00005` §6；
  清理口径留将来轮）
- 连带修改在同一会话内落地（共写写域使然；连带由人对关系文档另行
  处理）
- 跨文档的标注汇总视图、搜索、导出
- 为标注新增编辑锁或运行期只读之外的呈现（共写既有的非等待期只读
  与缓冲重载照常，本 spec 不加码）
- 多人协作语义（本地单人形态）
- `docs/` 之外文件的标注

## 7. Open Questions

无——本能力立项以来的全部域主裁决（idea 阶段十项与 prd 阶段两项，
记于 `idea-00003` 已定方向与 `prd-00002` 功能需求正文，两文档的
Open Questions 均已闭合删除）与 spec 审计轮的四项均已落成条文：
复用共写而非新立
会话种类、提交前须无未保存改动（缓冲孤儿的堵法；对全部提交一体
适用，因锚校验以磁盘为准对两通路同源）、issue 对文档类型不守门
（同共写口径，提交入口明示将转 `draft`）、question 受总并发上限
约束（「不占名额」仅指不占文档），均经域主逐条确认并已回写
`idea-00003`/`prd-00002`。本 spec 的条文级落定（随本 spec 评审一并
接受或推翻）：锚的恰一处命中（键含上下文、创建期歧义同拦）、提交
在途拒绝、分派次序先共写后 question、agent 选择逐通路各取缺省、
`spec-00006-FR-4` 的 Source 视图一次覆盖对标注来源不适用、流转
commit 失败沿 `spec-00001-FR-20`（会话照常启动）。预览选区映射、
锚数据形态与重定位细则、标注列表的呈现归属委给两份 design 的修订
轮（§5）。
