# Decision: 白板增设配置排除与目录组——推翻 decision-00016 §3「画布内折叠」一行，部分推翻其「按物理目录归组」一行与 §5、decision-00002 §2 与 §4

> 两件事一起定：`whiteboard.config.yaml` 增 `exclude` glob 列表，命中的文件对
> 白板**不存在**；类型目录的**第一级子目录**在其类型列内折叠为一个**目录组**节点，
> 导航栏同构呈现，展开态两处共享。类型仍是分列依据，目录只是类型列内的第二级
> ——`decision-00016` §3 对「目录替代类型分列」的否决维持，被推翻的是同表
> 「画布内折叠或分页长列」一行、以及 §5「归组依据不得改为物理目录」的绝对表态；
> `decision-00002` §4「本决定不做纵向分页或折叠」改为「不按数量分页或折叠，只按
> 目录折叠」。

## 1. 需要做这个决定的原因

- 白板的扫描是递归取 `docs/` 下全部 `.md`（`spec-00001-FR-1`，`docRepository.ts`
  `listDocFiles`），只跳过文件名为 `README.md` / `TEMPLATE.md` 的文件
  （`spec-00001-AC-1.3`）。一个采用本模板的仓库（creator-ai-hancock，2026-09-03
  评审对话中由域主给出，数值为域主口述、未在本仓复核）在 `docs/reference/` 下有
  1374 份 `.md`，其中 1356 份是 `<供应商>/source/` 里抓取的官方文档镜像：没有
  front matter、没有 id、没有关系。按今天的规则它们全部落到最右的 `untyped` 列
  成为 1356 个「front matter is missing」异常节点，异常清单同样多出 1356 条，
  整块板被淹没。这些文件不满足 `docs/reference/README.md` 对 reference 的定义
  （带 `id`/`type`/`status` 的 living doc），它们是语料，不是文档；白板没有任何
  办法说「这些不算」。
- 同一仓库把合式的 reference 也按供应商放进子目录（`stripe/`、`ccbill/`、
  `netbilling/`、`manifest/`）。画布与导航栏对目录一无所知：一个类型有几百份
  文档就是几百行，`decision-00016` §2 第 7 条「类型组缺省折叠」只把首屏从几
  百行压成一个组头，点开仍是几百行。
- 域主于 2026-09-03 的评审对话中逐项裁定：排除规则放流程配置而非每目录一份
  ignore 文件；折叠单元是类型目录的第一级子目录、不再嵌套；折叠组在列内占一个
  节点位并汇聚边；列内顶层文档在前、目录组在后。

## 2. 决定

| # | 做法 | 理由 |
| --- | --- | --- |
| 1 | **`whiteboard.config.yaml` 增 `exclude`**：相对 `docs/` 的 glob 列表，只在启动时读取（改动经重启生效，与其余字段同口径）；缺失、`null` 或空列表即不排除；不是字串列表、含空串、含 `..`、含 `\`、以 `/` 或 `!` 起头的模式即拒绝启动（与 `max_sessions` 同口径） | 「什么算板上的文档」是项目层的裁定，与类型、入口、关系矩阵同源；一处可读、可测、可 review。域主裁定 |
| 2 | **命中即不存在**：不成节点、不进异常与诊断、不可被命令面板检索、其文档 id 与正文条目 id 都不可被关系字段或行内 id 跳转解析（指向它的边按断链处置）、文件变更不改变图 | 半存在（不显示但可被引用）会造出一类「图上找不到的边终点」；不存在是唯一没有例外的语义——它也不占 `rule-00001-BR-18` 的号、不参与撞 id 判定（域主 2026-09-03 裁定：不存在没有例外） |
| 3 | **glob 语义**：`*` 不跨 `/`、`**` 跨任意层；只匹配文件路径（`reference/stripe` 不命中其下文件，要写 `reference/stripe/**`）；区分大小写；不支持 `!` 取反；命中为空或命中全部都不是错误 | 与 gitignore 的目录形态分道是有意的：gitignore 的「目录名即其下全部」是对目录的语义，这里匹配的是白板读到的文件清单；不做隐式扩展就没有第二套规则可猜。取反在无实例前不加 |
| 4 | **目录组是类型列内的第二级**：列仍由 front matter `type` 决定（`decision-00002` §2 不动）；同一列内、`docs/` 下路径前两段（`<文件夹>/<子目录>`）相同的文档成一组；路径不足三段的文档（顶层文档，含直接位于 `docs/` 下者）不成组；组键即那两段路径 | 保住 `decision-00016` §2 第 2 条的实质——画布与导航栏镜像同一顺序、`type` 缺失或与目录不符时不分歧——因为分列依据没变；目录只在列内再分一层。组键取两段路径，同列内两个不同目录永不同键 |
| 5 | **只折一层**：更深的层级全部归入其第一级子目录；**不设数量阈值**：一份文档的子目录也成组，可见文档为零的目录不成组 | 任意深度的嵌套在画布上没有可读的形状，现有仓库也没有这个需要；阈值折叠已在 §3 否决，所以一份也折——规则只有一条 |
| 6 | **折叠态**：目录组在其列内占一个节点位，呈现组名与文档数；组内任一文档异常则组节点带异常标记；组内任一文档有会话则组节点带会话标记（组内有任一会话等待输入即取等待态，否则运行态；激活该标记只展开目录组，会话从展开后真节点上的标记进入）；组内文档不作为节点呈现；组内文档与外部节点之间的边落到组节点上、按 `spec-00001-FR-28` 的既有口径合并（同一对、同方向合为一条，标签并列全部字段名）；组内互指的边不呈现；组节点沿用文档节点的呈现与压弱、其边沿用弱化态与强调态，不另立节点级的「强调」 | 折叠的意义是把 N 行压成 1 行而不丢信号：数量、有没有坏的、有没有在跑的三件事仍在一眼可见处；边的合并沿用既有口径而不另立 |
| 7 | **原地展开，不下钻子画布**：点击组节点即展开或折叠；展开后组内文档按行序紧随组节点之下成为普通节点，边随之拆到各自的真节点上 | 子画布是只读的（`spec-00001-FR-35`/`FR-37`：不提供任何写入口）；目录里的是真文档，要编辑、流转、答疑、起会话，全部动作只在顶层节点上存在。下钻会为目录复制整套节点动作，原地展开一个都不必复制 |
| 8 | **展开态画布与导航栏共享**、按「列 × 组键」持久于浏览器本地、**缺省折叠** | 两处对同一集合各记一份展开态，用户会在一处点开、另一处看不见。共享是「同一份模型」（`design-00002` §17.2）的自然延伸；缺省折叠与类型组同口径（`decision-00016` §2 第 7 条） |
| 9 | **列内顺序：顶层文档（id 序）在前，目录组（组键字典序）在后；组内按 id 序、同 id 按路径** | 顶层文档是这个类型的「正文」，子目录是它的分册；分册排在正文后面。组内沿用 `decision-00002` §2 的行序，不另立规则。域主裁定 |
| 10 | **选中变化落到折叠组内的文档时自动展开该组**——命令面板、三份清单、关系列表、导航栏、会话面板、行内 id 跳转、详情面板的 record 跳转皆然（面包屑返回不改变选中，不在此列）；用户手动折叠含选中文档的组时该组保持折叠，选中不清、组节点取选中态呈现 | 与 `spec-00008-FR-3`/`FR-4` 对类型组的既有裁定同构：展开只随选中**变化**发生，不随折叠动作反弹 |
| 11 | 子目录内的 `README.md` 与 `TEMPLATE.md` 继续不作为文档（`spec-00001-AC-1.3` 不变），也**不**用作组名 | 读 README 取标题要定义「哪一行是标题」，多一条解析约定换一个装饰性收益；目录名本身就是作者起的名字。组名：组键第一段与列类型同名时只呈现第二段，否则呈现两段——只有放错目录的文件才会看到两段（域主裁定） |

## 3. 考虑过的其他选项

| 选项 | 结论与理由 |
| --- | --- |
| 每个类型目录放一份 `.whiteboardignore` | **否决**（域主裁定）。配置分散到各目录，与流程配置「一处声明」相悖；`exclude` 一个字段承担同一能力 |
| 用 front matter 字段（如 `board: false`）逐文件退出 | **否决**。要排除的恰是没有 front matter 的语料，逐文件加字段等于给 1356 份镜像补 front matter |
| 不加排除、只靠目录组折叠 | **否决**。1356 个异常节点在 `untyped` 列折成四个 `reference/<供应商>` 组，画布是干净了，但异常计数与异常清单仍是 1356 条；语料不是坏文档，不该以异常的形态存在于板上 |
| `exclude` 的目录形态模式按 gitignore 语义命中其下全部 | **否决**（§2 第 3 条）。两套匹配语义并存时，`reference/stripe` 到底命中什么要靠猜 |
| 点开目录组下钻进子画布 | **否决**。子画布只读（§2 第 7 条）；目录里的文档需要顶层节点的全部动作 |
| 任意深度嵌套折叠 | **否决**。画布上没有可读的形状；现有实例一层即够；有需要再议 |
| 按数量阈值自动折叠长列 / 分页 | **否决**。折叠单元与作者的目录组织无关时，位置不再可预期（`decision-00002` §4 得到的「位置可预期」被换掉）；目录是作者有意的分册，数量不是 |
| 一份文档的子目录不折叠 | **否决**。这是变相的数量阈值（阈值 = 2），且让「有没有组节点」随文档增删跳变 |
| 目录作为第一级、替代类型分列 | **否决**（维持 `decision-00016` §3 该行）。`type` 缺失或与目录不符时画布与导航栏分歧 |
| 语义缩放（缩到一定级别时列只画表头与计数） | **搁置**。排除与目录组落地后再看剩余规模是否还需要 |
| `exclude` 支持 `!` 取反 | **搁置**。无实例；有需要时作为叠加语义再议 |
| `exclude` 进设置面板（`spec-00009`）可视化编辑 | **搁置**。先手改 YAML；需求出现再进设置面板 |
| 组节点用组内 README 的 H1 作标题 | **搁置**（§2 第 11 条）。目录名足够 |

## 4. 后果

**接受的代价**

- 展开一个目录组会把其下方的节点整体下移——`decision-00002` §4「位置可预期」
  在**列内**变为「给定展开态时可预期」：同一展开态下位置恒定，展开态改变时
  该列组节点以下的行移动。缓解：展开态持久，用户不常切换；跨列位置完全不受
  影响。这直接回应 `decision-00016` §3「折叠后节点位置不再可预期」的否决理由：
  折叠单元是作者的目录组织而非数量，位置仍是（图、配置、展开态）的纯函数。
- 折叠时组节点上的汇聚边**丢失对端细节**：外部文档指向组内三份文档的三条边合
  为一条、不标数量；展开后即拆开。与 `spec-00001-FR-28` 已接受的合并代价同类。
- `exclude` 是又一处「远距离作用」：写错一条 glob 会让一批文档从板上消失而
  没有任何异常提示（不存在即无提示），`exclude: ['**']` 得到一块空板。缓解：
  配置文件就地注释；`exclude` 形态非法时拒绝启动而非静默忽略；命令面板检索
  不到即可察觉。
- 被排除文件的 id **不占号、不报撞 id**：一份带 id 的被排除文件与白板新建的
  文档可能在磁盘上真撞 id 而白板不报。接受：该被排除的本不该带 id；
  `docs/README.md`「全仓唯一」加注为白板可见的文件。
- **展开态的键含列与目录**：目录改名、或组内文档改 `type` 而换列时，旧键失效、
  该组从缺省折叠起，用户的展开态静默丢失。无缓解；改名与换列都少见。
- 不配 `exclude` 时目录组只把**画布**压成几个组节点：异常计数与异常清单仍逐份
  计入、命令面板仍全量可检索、解析仍逐文件进行。目录组解决「太多」，不解决
  「不该在」；后者只有 `exclude`。
- 浏览器本地新增一处持久状态（各目录组展开态）；清除站点数据即回缺省，不影响
  `docs/`。

**得到的**

- 语料与文档的边界由项目自己声明，白板只呈现文档；hancock 一类仓库的板从
  1300 多个红节点回到几十个真节点。
- 一个类型有几十上百份文档、按目录分册时，首屏是「正文 + 几个分册」，点开
  才见分册内容；画布与导航栏看到同一份结构。
- 即便项目不配 `exclude`，没有 front matter 的深层文件也会按目录折成一个组，
  **画布**首屏不再被淹没（异常计数与清单照旧，见上）——排除解决「不该在」，
  目录组解决「太多」，两者独立成立。

**不变的**

- 分列依据（front matter `type`）、列序（流程配置声明顺序）、异常与未知类型
  的落位（`decision-00002` §2）全部不变；目录组只在列内起作用。
- 节点的四槽信息层级（`design-00002` §4：类型、状态、标题、id）不变；组节点是
  **另增**的一种形态，不改文档节点。
- 命令面板的检索与跳转**通路**（`spec-00001-FR-26`/`FR-27`）不变；可检索的
  集合随 §2 第 2 条收窄，跳转落到折叠组内时多一步自动展开（§2 第 10 条）。
- 类型组的折叠与持久化（`spec-00008-FR-4`）不变；组内文档是普通节点，展开后
  一切动作照旧。
- 子画布仍只服务 spec/rule 的需求条目（`spec-00001-FR-35`）；目录组不使用它。
- 文件名为 `README.md` / `TEMPLATE.md` 的排除规则不变，`exclude` 是叠加而非替换。

## 5. 这个决定约束什么

- `spec-00010-whiteboard-directory-groups-and-exclude`：全部 FR 以本决定为前提。
- `spec-00001-docs-whiteboard`：FR-1 的扫描范围（减去 `exclude` 命中者）与列内
  行序（顶层文档之后接目录组）、FR-15 的配置键枚举（增 `exclude`）——随
  spec-00010 接收在原文追注（`spec-00003` 对 `spec-00001-FR-14` 的追注先例）。
- `spec-00002-whiteboard-governance`：FR-8 撞 id 的判定集合收窄为可见文档
  （`spec-00010-FR-11`），与 `docs/README.md` 的「全仓唯一」「每一份声明它的
  文件」两句一并原地追注（域主裁定）。
- `rule-00001-docs-workflow`：BR-18「该类型现有最大编号」以白板可见文档为准
  （`spec-00010-FR-12`）——原地追注。
- `spec-00003-whiteboard-parallel-sessions`：FR-10 节点会话标记在组节点上以
  聚合形态出现、激活只展开——原地追注。
- `spec-00008-whiteboard-navigation-sidebar`：FR-1（组内不再是平铺）、FR-3
  （选中联动须一并展开目录组）、FR-7（折叠组一个缩略块）与 §6 Out of Scope 的
  两条（「按物理目录归组」「画布内的列折叠」）——同样原地追注。
- `design-00001-docs-whiteboard`：§3 流程配置契约增 `exclude` 字段、glob 语义
  与校验；§2 模块结构中 `docRepository` 的扫描范围改为「递归减去排除」；§11
  写明共写收口对被排除路径沿用现状——读不出文档即判不合式并删除（域主裁定）。
- `design-00002-whiteboard-ui`：§1 令牌表增组节点令牌色；§2 布局的列内构造增
  目录组一层；§4 增组节点形态、聚合标记与压弱；§17.1 持久化与 §17.2 内容构造增
  目录组一层；§17.3 选中联动扩到目录组；§17.4 缩略图增折叠组的着色；需一节承载
  目录组的界面设计（新修订轮）。
- `decision-00016` §3「按物理目录归组」一行与 §5「归组依据不得改为物理目录」
  一句：**部分推翻**——分列依据仍不得改为目录，目录得作为列内第二级归组。
  `decision-00016` §3「画布内折叠或分页长列」一行：**推翻**——折叠单元是目录
  而非数量，位置在给定展开态下仍可预期（§4）。本决定进 `active` 时在原文三处
  原地追注指向本决定（`decision-00011` 的追注口径）。
- `decision-00002` §2「同列内按文档 id 升序」的行序与 §4「本决定不做纵向分页或
  折叠」一句：**部分推翻**——行序在顶层文档之后接目录组；仍不按数量分页或
  折叠，按目录折叠由本决定引入。同样原地追注。
- 站立约束：`exclude` 的语义只能是「不存在」，不得引入「隐藏但占位」的中间态；
  目录组不得嵌套；分列依据不得改为目录；不得为目录组引入 `docs/` 之外的排序
  或命名状态。后续落到本决定之下的 `plan` 回填进本文件的 `constrains`。
