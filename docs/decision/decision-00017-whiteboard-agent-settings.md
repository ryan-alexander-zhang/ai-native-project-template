# Decision: agent 设置分两层——项目层随仓库、本地层由设置面板写，模型进条目

> agent 条目增 `model` 与 `env` 两键、`{model}` 占位符；`whiteboard.config.yaml`
> 的 `agents` 是团队共享的项目层，`.whiteboard/` 下新增一份不入 git 的本地
> agent 设置（本地层），由白板顶栏的设置面板读写；两层按名合并为有效 agent
> 列表，此后一切「流程配置 `agents`」的读处改读它。白板仍不直连模型、不认识
> 任何 CLI 的参数名。

## 1. 需要做这个决定的原因

- `whiteboard.config.yaml` 的 `agents` 今天只有一条 `claude`，且没有模型的
  席位：想换模型只能把 `--model x` 塞进 `args`，答疑的 headless 形态还得在
  `first` 与 `resume` 两处各塞一遍——三处手改、无一处能在界面上看见。
- 该文件是**已提交**的项目文件，而「装了哪个 CLI、订了哪个套餐、想用哪个
  模型」是每台机器、每个人自己的事。今天要么改共享文件（协作者的机器跟着
  变），要么每人本地保留一份未提交改动（每次 pull 都要处理）。
- 该文件的注释承载接入验证的审计记录（`spec-00001-AC-13.2`、design-00001
  §3 / §10.1 / §11.5 的「未实测不进默认配置」纪律）；任何由界面生成 YAML
  的做法都会把这些注释冲掉。
- `agents` 的 `command` 是要执行的可执行文件。一个能写已提交文件的界面，
  等于任何协作者一次点击就能改动别人机器上会启动的程序。
- 多 agent 的选择与缺省口径由 `decision-00008` §2 第 4 条立下
  （`spec-00001-FR-55`：可指定其一、未指定取第一条）；本决定不推翻它，只
  改变它读的对象。
- 域主于 2026-09-02 的评审对话中提出：agent 应可配置，「最起码要能配置使用
  的 Model」，并要求「在 UI 界面也可配置」、作为项目的设置项。

## 2. 决定

| # | 做法 | 理由 |
| --- | --- | --- |
| 1 | **agent 条目增 `model`（可选非空字符串）与 `env`（可选字符串映射）**；`{model}` 占位符可出现在 `args`、`headless.first`、`headless.resume`，构造命令时每处替换为条目的 `model`——这把占位替换**新扩展到终端形态的 `args`**（今天只有 headless 声明做替换）；`env` 叠加进子进程环境，两个 spawn seam 皆然 | 各 CLI 的模型参数名不同（claude `--model`、codex `-m` / `-c model=`），写死在代码里等于替每个 CLI 维护一份适配。`{question}` / `{session}` 的占位语法已在（design-00001 §10.1），`{model}` 沿用同一语法、多覆盖一条路径，代码对 CLI 保持无知。`env` 是 Zed / ACP 一族 agent 配置都有、我们缺的键——靠环境变量控行为的 CLI 会需要 |
| 2 | **`model` 与 `{model}` 按形态成对**：有占位无值拒绝；有值则 `args` 须含占位，且声明了 `headless` 的，`first` 与 `resume` 也各须含占位；`model` 为空串同拒绝。项目层违反按 `spec-00001-FR-15` 拒绝启动并点名。**读法：条目的 `model` 对该条目的每一种形态都生效**——不支持「只给答疑指定模型、交互用 CLI 自己的缺省」；要那样就写两条 | 有值无占位是**静默失效**——界面上填了模型、进程里却没用上——正是要在校验期抓住的那类错；只查 `args` 不查 headless，会让模型在交互形态生效、在答疑形态悄悄消失，恰是 §1 第一条描述的痛点。「一条一个模型」比「按形态各一个」少一套键，且两条条目已能表达后者 |
| 3 | **两层配置**：项目层 = `whiteboard.config.yaml` 的 `agents`（不变、随仓库）；本地层 = `.whiteboard/agents.json`（不入 git，`.whiteboard/` 已在 `.gitignore`） | VS Code 的 user / workspace 两层、Claude Code 的 `settings.json` / `settings.local.json`、git 的 `config` / `config --local`——同一问题的通行解。`.whiteboard/` 已是本机运行态的家（会话日志、答疑线程、澄清状态），不新造目录。取 JSON 而非 YAML：它由界面写、与同目录其他文件同型，且无注释可丢 |
| 4 | **合并规则**：按条目名合并；本地键覆盖项目键，**`cwd` 除外**；本地追加条目（须自带 `command`；`cwd` 不可声明、恒为 `docs`——屏障对追加条目同样成立，否则一张表单就能造出跑在仓库根的 agent）排在项目条目之后；本地可**禁用任意条**（不进有效列表，发起时按未知名拒绝）、可**指定至多一条为缺省**（排到有效列表首位）；覆盖、禁用或缺省所指的项目条目已不存在时**单条忽略**并在面板点明（`git pull` 后项目层改名不应打坏本地层） | `cwd: docs` 是写域的第一层屏障（design-00001 §3），本地层不得松动它。缺省用「排首位」表达，是为了保住 `decision-00008` 立下的「未指定取第一条」规则本身——`spec-00001-FR-55` 与 `spec-00005-FR-2` 的**规则**不改，改的只是它们读的那个名词 |
| 5 | **一切读 `agents` 的地方改读有效 agent 列表**：`spec-00001-FR-55` 的选择与缺省、`spec-00005-FR-2` 的 headless 可选集、`spec-00007-FR-5` 统一提交的两个可选集、配置下发；有效列表**按次重新计算**（每次会话发起受理、每次配置下发），不在启动时定格 | 一个事实来源；本地层若只影响其中一处，用户会在另一处看到旧列表。按次计算是「保存即生效」与「手改文件也生效」的前提 |
| 6 | **本地层不合式不拦启动**：解析失败、条目校验不过、覆盖了 `cwd`、追加条目无 `command` 或声明了 `cwd`、缺省多于一条或指向禁用条目、合并后为空——本地层**整体**忽略（不是只丢违规的那一键）、退回项目层，设置面板呈现原因、服务端记录告警 | 项目层坏了拒绝启动（FR-15）是因为它是团队契约；本地层是个人便利，一份手改坏的本地文件不该把整个工具锁死。整体忽略而非逐键丢弃：部分生效的配置比不生效更难排错。界面保存前先校验（不合式拒绝、不落盘），本地文件只会因手改而坏 |
| 7 | **设置面板**：顶栏入口，列出有效列表每条的来源（项目 / 本地 / 项目+本地覆盖）与各键；可对项目条目覆盖除 `cwd` 外任意键（**含 `command`**——`claude` 不在 PATH 时写绝对路径是本机的事）、追加本地条目、禁用、设为缺省、删除本地条目或撤销本地覆盖；**`model` 是自由文本**；**`env` 值缺省遮罩、逐项点击显示**；本地追加的条目旁呈现「该 CLI 未经写域校验，由你自负」的说明 | 白板不认识任何 CLI 的模型列表，下拉框等于替每个 CLI 维护一份会过期的清单；自由文本 + 校验期报错足够。写域校验是人做的实测（design-00001 §11.5），界面不假装替代，只把责任说清 |
| 8 | **保存即生效于其后受理的会话与调用**；受理即把条目解析为命令、参数、环境、工作目录的**快照**，已受理的（运行中、或已受理尚未起进程）按快照进行——包括其间被删掉的本地条目；统一提交按整批受理一次；保存后**只有发起保存的页面**即时换列表，其他页面下次重新加载见新列表（变更推送不为设置增触发源）；追问时线程记录的 agent 已不在有效列表或不再声明 headless 则拒绝追问、线程不受影响 | 会话受理时已解析好命令与环境，中途换配置没有语义。追问要用该条目的 `resume` 形态构造命令，条目没了或 headless 没了就构造不出来——拒绝比猜一条替代更诚实（`spec-00005-FR-2`：接续只对原 CLI 有效） |
| 9 | **不做 Codex 接入本身** | 接入需要新的 capture 内建（design-00001 §10.1「一个 capture 一种读法」）与两种形态的实测门；那是另一份 spec 的事。本决定只保证接入时配置层不再是障碍 |

## 3. 考虑过的其他选项

| 选项 | 结论与理由 |
| --- | --- |
| 代码内建各 CLI 的模型参数名，配置只写 `model: x` | **否决**。等于替每个 CLI 维护适配，与 design-00001 §10.1「capture 是代码内建、配置只引用」的分工相反——那里内建的是**输出读法**（不得不），这里参数名配置就能表达 |
| 界面直接改写 `whiteboard.config.yaml` | **否决**。冲掉注释里的接入验证记录；把个人机器的选择写进共享文件；`command` 可被协作者远程改动 |
| 白板直连模型 API，配置 provider + model + key（Cursor / Cline / OpenCode 一族） | **否决**。前提不同：白板不直连模型，只起本地 CLI（prd-00001 功能需求 8）；权限、上下文、工具全由 CLI 承载 |
| 只加 `model` 键，不做本地层与界面 | **否决**（域主明确要求界面可配、作为项目设置项）。且不解决「个人选择写进共享文件」的问题 |
| 本地层用 `whiteboard.config.local.yaml` 放仓库根 | **否决**。要新加 `.gitignore` 规则、根目录多一个文件；`.whiteboard/` 已是本机态的家 |
| 缺省 agent 用显式 `default: <name>` 键而非排序 | **否决**。会改掉 `decision-00008` 立下的「未指定取第一条」规则本身，`spec-00001-FR-55` 与 `spec-00005-FR-2` 都得改规则；排序法只换名词 |
| 本地层允许覆盖 `cwd` | **否决**。`cwd: docs` 是写域第一屏障，本地层松动它等于绕过 `spec-00001-FR-13` |
| 本地层不许覆盖 `command` | **否决**。本机 PATH 里没有那个名字、要写绝对路径，是最常见的本地覆盖需求之一；本地层只影响本机，风险面与手改 PATH 相同 |
| 本地层不合式即拒绝启动（与 FR-15 同纪律） | **否决**。个人便利层不该锁死团队工具；界面保存前已校验，坏文件只来自手改，忽略 + 呈现原因足够 |
| 本地层不合式时只丢弃违规的那一键 | **否决**。部分生效的配置最难排错（「我明明改了模型为什么没用」）；整体忽略 + 面板点名，行为可预期 |
| 答疑单独一个缺省 agent | **否决**（域主 2026-09-02 裁定）。一个缺省 + 「答疑取有效列表中第一条声明 headless 的」已覆盖多数情形；交互与答疑要不同模型时，把两条都写进本地层、缺省指向交互那条即可。覆盖不了的只有「两条都有 headless 而答疑想用非首位那条」，需求出现再议 |
| `env` 值在面板明文呈现 | **否决**（域主 2026-09-02 裁定）。取「缺省遮罩、逐项点击显示」：屏幕共享时不泄露密钥，核对时一次点击可见；编辑态不遮罩 |
| `model` 做下拉框，选项由 CLI 提供 | **否决**。没有 CLI 提供稳定的模型枚举接口；清单会过期。自由文本 + 校验期报错 |

## 4. 后果

**接受的代价**

- 「有效 agent 列表」这一层间接：排错时要看两个文件。缓解是设置面板逐条
  标来源、配置下发携来源。
- `.whiteboard/agents.json` 可能含密钥（`env`）。它不入 git，服务只服务
  本机——「不入 git」与「适合放密钥」是两件事，后者由本机访问边界担保。
  面板呈现 `env` 值缺省遮罩、点击显示（§3）。
- `env` 不限制键名，`PATH` 可被覆盖而改变 `command` 的解析；能这样做的只有
  本机用户自己，接受。
- `model` 自由文本拼错，CLI 自己报错在终端 / 答疑失败态，白板不预检。
- 单机单人工具，两个浏览器标签同时改设置以后写为准；不做并发保护。
- **`spec-00001` 与 `spec-00005` 各须进一轮修订轮**：`spec-00001-FR-55` 与
  `AC-55.4` 的「流程配置 `agents`」换为「有效 agent 列表」——是名词替换，
  规则不变；但 `AC-55.4` 的 Given「流程配置只声明一条」在本地层追加一条时
  不再蕴含其 Then，不改会被 spec-00009 的 AC-8.1 直接证伪，故不能算笔误级。
  `spec-00005-FR-8` 的「流程配置的 agent 条目」与「不合式拒绝启动」同样要
  换：本地层条目也可声明 headless，其不合式不拦启动。

**得到的**

- 换模型、换 CLI 参数、加环境变量，都在界面上做，不碰共享文件、不丢注释。
- 团队共享的项目层保持干净：写进去的每条都过了接入验证纪律。
- Codex 一类 CLI 接入时，配置层已备好 `env`、`{model}` 与本地试用的路径。

**不变的**

- `spec-00001-FR-13` 写域约束、`FR-15` 项目层启动校验、`FR-55` 的选择与缺省
  **规则**；`spec-00005-FR-2` / `FR-8` 的 headless 声明与可选集规则；
  `spec-00007-FR-5` 的两个可选集。除 `spec-00001-FR-55` / `AC-55.4` 与
  `spec-00005-FR-8` 换名词外文字不改，
  它们读的对象从「配置 `agents`」变为「有效 agent 列表」。
- `whiteboard.config.yaml` 的现有键、模板仓库自带的一条 `claude` 不变。
- 接入验证纪律（design-00001 §3 / §10.1 / §11.5）不变：进**项目层**仍须实测；
  本地层是用户自己的机器、自己的责任。

## 5. 这个决定约束什么

- `spec-00009-whiteboard-agent-settings`：全部 FR 以本决定为前提。
- `spec-00001-docs-whiteboard`：`FR-55` 与 `AC-55.4` 的名词替换（修订轮）。
- `spec-00005-whiteboard-ask-threads`：`FR-8` 的名词替换与本地层条目的
  不合式处置（修订轮）。
- `design-00001-docs-whiteboard`：§3 流程配置契约增 `model` / `env` 键与按
  形态的成对校验；§10.1 命令构造增 `{model}` 替换（两条路径）与 `env` 叠加
  （两个 spawn seam）；§7 API 增设置端点、配置下发改为有效列表并携来源；
  新增一节承载本地层文件形态、合并规则、不合式降级与按次重新计算；front
  matter `informs` 增 spec-00009（修订轮）。
- `design-00002-whiteboard-ui`：新增一节承载设置面板；front matter `informs`
  增 spec-00009（修订轮）。
- `whiteboard.config.yaml`：模板自带的 `claude` 条目可增 `model` 与
  `{model}`——但按纪律，写入前须对当前 claude 版本实测 `--model` 在两种形态
  下生效。
- 站立约束：代码不得内建任何 CLI 的模型参数名；本地层不得覆盖 `cwd`；
  设置面板不得写 `whiteboard.config.yaml`；有效列表不得在启动时定格；后续
  落到本决定之下的 `plan` 回填进本文件的 `constrains`。
