# Decision: 存量文档立债不翻新，新档从严、触碰即修

> 对 270 份早于现行体系的存量文档：确定性错误当轮修复，内容契约缺口
> 登记为债务而不回写历史；此后新建与修订触碰的文档按现行模板全量达标。

## 1. 需要做这个决定的原因

2026-08-31 本分支合入 main 演进后的 docs 体系（模板、验收推导、record
惯例、解析契约），随后的全量排查
（[report-00004](../report/report-00004-docs-conformance-audit.md)）发现
270 份存量文档无一完全符合现行 README/TEMPLATE——它们写于体系演进
之前。全量翻新、选择性翻新还是立债，必须择一。

## 2. 决定

| # | 做法 | 理由 |
| --- | --- | --- |
| 1 | 存量内容契约缺口立债不翻新，底册为 report-00004 §3 | 历史文档是已完成工作的实录；事后补 `Introduced by`、验收现场等属追认编造，证据链失真 |
| 2 | 新建文档与进入修订轮的存量文档按现行 README/TEMPLATE 全量达标（触碰即修），欠项不齐不回 active | 债务随日常工作自然收敛，无需专项翻新工程；与 CODE_QUALITY.md §8「new 从严、legacy 登债」同一原则 |
| 3 | 确定性错误（关系字段、编号、死链、非法字段、词表、AC 归属、wikilink）不属债，当轮修复 | 改法唯一、语义零损，机器可读契约必须即时成立——白板解析零诊断是硬门 |
| 4 | resolved plan 的 record 欠账登记不回补；record-00001 的既有不符留史，仅修死链 | 事后造 record 缺当时验收现场；record 即证据、不回改 |
| 5 | 带未决 Open Questions 的 active 文档降回 draft（analysis-00008/00012/00013、design-00001/00012） | 促进门如实执行；未决项该在板上看得见 |

## 3. 考虑过的其他选项

| 选项 | 结论与理由 |
| --- | --- |
| 全量翻新 270 份 | **否决**。169 份 resolved issue 的 `Introduced by` 需逐份考古，大量无法考证者只能编造；工程量与失真风险都不可接受 |
| 选择性翻新（仅 spec/design/decision 32 份） | **否决**。翻新同样要逐份语义裁决，收益不抵投入；触碰即修最终覆盖同一集合且按需付费 |

## 4. 后果

**接受的代价**

- 板上存量文档与模板形态长期不齐，spec 覆盖与最小集缺口持续可见——
  以 report-00004 为对账底册，可查可清。

**得到的**

- 历史实录不失真；精力留给新工作；债务有单、收敛有径。

**不变的**

- 机器可读契约（id、status、front matter 字段集、条目文法、引用完整性）
  不在债内——本轮已全部达标，此后任何提交都不得使白板解析出现诊断。

## 5. 这个决定约束什么

- 本分支此后全部文档工作：新建即达标；存量文档的任何修订轮（含共写、
  澄清、审计会话的落笔）须顺带清偿该文档在 report-00004 §3 中的欠项，
  欠项未清不回 active。
- 债务底册的维护：清偿后在 report-00004 划账；清零后归档该报告。
- 不得再引入 wikilink、时间戳 id、越界关系字段等已修复类别的回潮。
