# Decision: 解除单会话约束，多会话并行进入规格

> 推翻 `decision-00008` §3 对「多会话并行」的否决行：该否决是 MVP 的范围
> 裁剪，不是产品立场。并行的并发模型、上限、等待输入判定、通知与收尾
> 串行化在此一并裁定，由 `spec-00003-whiteboard-parallel-sessions` 承载。

## 1. 需要做这个决定的原因

- 单会话约束（`spec-00001-FR-18`）在实际使用中构成瓶颈：负责人同时对多份
  文档发起澄清或答疑时被迫串行排队；收起终端后无从知道哪个会话在等自己
  输入。
- 该方向有在案否决：`decision-00008` §3「多会话并行——否决（域主裁定，
  维持 spec §6 Out of Scope）」，且 `decision-00006` §5 规定重开须先出示
  单会话瓶颈的实录。`spec-00003` 草拟后的审计指出：不先裁决此门，spec
  不可接收。
- 一并需要裁定的还有并行带来的一组新问题：并发模型与上限、等待输入的
  判定手段、多会话结束时的通知与刷新、commit 收尾的串行化、服务端重启
  的处置——`spec-00003` 初稿把它们列为 Open Questions，本决定逐条关闭。

## 2. 决定

| # | 做法 | 理由 |
| --- | --- | --- |
| 1 | **推翻 `decision-00008` §3 的「多会话并行」否决行**，并行进入规格（`spec-00003`）。`decision-00006` §5 的实录门槛由域主裁定**豁免**；`decision-00006` §2 第 7 条与 `decision-00007` §4 对单会话约束的采纳与复述一并被推翻（会话通道与 commit 粒度不动，只改互斥模型）。上述各处均已**原地追注**（decision-00007 追注 decision-00004 的先例） | 当时的否决理由是「改动面配得上单独一轮」——是 MVP 的范围裁剪，本轮就是那单独一轮；实录门槛的当事人（被瓶颈拖住的负责人）即域主本人，直接裁决替代实录 |
| 2 | **并发模型**：同目标文档互斥 + 运行中总数上限，四种会话（推进、澄清、答疑、审计）一视同仁；推进的「目标文档」取其来源文档（`spec-00001-FR-19` 的既有口径） | 写冲突的主干被文档粒度互斥守住；推进的 id 由服务端在发起时串行分配（`spec-00001-FR-11` 任务指令携带 id）**且已分配给发起中会话的 id 参与后续取号**（`rule-00001-BR-18` 只看盘上文件，若无保留，两个并行推进会拿到同一个号——保留是并行的必要机制），并行推进无撞 id 风险；单一规则免去「哪几种能并行」的双轨制 |
| 3 | 上限由流程配置**新键 `max_sessions`** 声明，**缺省 3**；UI 呈现「运行中数/上限」 | 人的注意力约能交错应答 3 个会话，更多只是排队占资源（每会话一个完整 CLI 进程）；可配置留给例外，呈现让拒绝可预期 |
| 4 | **启动失败的会话不占槽位**（槽位在服务端受理发起时占用、启动失败即释放），以「失败」入会话面板，**并同样以提示条通知** | 进程没起来就没有资源占用，槽位记账跟随真实进程；失败必须可见——它恰是最需要被看见的结束态，否则用户以为会话在跑 |
| 5 | **最后一个槽位的竞争**按服务端接收顺序先到先得，后到者按上限拒绝 | 发起都经同一本地服务端，天然可串行判定，无需新机制 |
| 6 | **会话面板的已结束窗口取本次服务启动以来**（工作集）；全部历史仍归 `spec-00001-FR-54` 的会话历史（档案），不设额外清理 | 两个面向不同：面板管「现在该处理谁」，历史管「过去发生过什么」；per-boot 窗口天然有界 |
| 7 | **等待输入取弱语义**：连续无输出达到静默阈值（实现常数，量级 10s，定死在 design、不进配置）且进程存活即判定；允许误报 | CLI 不上报等待状态，PTY 读阻塞探测跨 CLI 不可移植；该标记只驱动徽标与通知、不驱动状态机或 commit，误报代价近零；弱语义使 FR 可确定性测试 |
| 8 | **提示条逐条堆叠、不合并**；同批结束触发的**刷新合并为一次**；板外通知（浏览器 Notification 等）维持范围外 | 同时结束的数量被上限封顶，为罕见小数量做合并逻辑不值；刷新幂等、呈现状态按 id 保持，合并纯赚；板外通知牵扯权限 UX，值得单独一轮 |
| 9 | **收尾 commit 全局串行**：会话结束 commit 与用户动作 commit（`spec-00001-FR-14`）进同一队列；两个会话写同一文件的残余归属按结束顺序，先结束者的 commit 允许含对方对该文件的变更——**作为已知噪音接受**。（实现轮推广，原地追注：内容差集不携带归属，故该归属边界适用于对方快照后写入的**任何路径**、不限同一文件——写入与收尾重叠即适用，非罕见同刻；据此产生了变更的会话可因收尾时无残余而不产生 commit，`spec-00001-FR-14` 的「一会话一 commit」相应读作「至多一次」（已于其原文追注）。理由列的「残余情形极少」按此重读：同目标互斥使各会话自己的目标文档不相撞，残余限于对方快照后的重叠写入。变更不丢失的保证不变，`spec-00003-FR-8` 第十六轮 T5 修订记之） | 残余情形极少（两个会话都去写同一份第三方文档），本地单人 + git 历史可追溯，接受噪音比精确归属算法便宜；唯一能从源头消除它的「关系文档互斥」已在 §3 否决（在高连通的 docs 图上等价全局锁） |
| 10 | **不承诺跨服务重启存续**：正常关停时对运行中会话执行终止的收尾（commit 与历史落盘），异常崩溃不保证；重启后面板空态。**「终止」一词随之扩义**：服务端正常关停时对运行中会话的收束视同终止（`CONTEXT.md` 词条增补） | 跨重启保活需要 tmux 式 PTY 脱离托管，对本地工具是不成比例的复杂度；「关停即终止」复用已有语义，同一收尾不造第二个词 |

## 3. 考虑过的其他选项

| 选项 | 结论与理由 |
| --- | --- |
| 维持单会话（现状） | **否决**（域主裁定）。MVP 裁剪的理由已不成立，瓶颈已在实际使用中出现 |
| 互斥扩展到「目标及其关系文档」 | **否决**。docs 图高连通（spec-00001 与 spec-00002 同 parent 即互相锁死），等价全局锁 |
| 仅放开澄清与答疑，推进与审计维持互斥 | **否决**。担心的推进撞 id 不存在（id 发起时串行分配）；双轨制比单一规则贵 |
| 等待输入走 PTY 读阻塞探测 | **否决**。对 claude / codex 等不同 CLI 不可移植、脆；弱语义的误报代价近零 |
| 静默阈值进配置 | **否决**。没有用户会想调它，开配置是伪灵活性 |
| 多会话结束的提示条合并 | **否决**。数量被 `max_sessions` 封顶，合并逻辑不值 |
| 跨服务重启保活运行中会话 | **否决**。tmux 式托管复杂度不成比例 |
| 同文件写冲突做精确归属算法 | **否决**。残余情形极少，git 历史可追溯；按结束顺序 + 已知噪音更便宜 |

## 4. 后果

**接受的代价**

- 等待输入提醒有约一个阈值的延迟，且偶发误报（模型长思考时错亮徽标）；
  代价是多瞥一眼。
- 两个会话写同一文件时 commit 归属有已知噪音（先结束者可能带走对方的
  变更）；缓解是逐文档互斥使其只发生在「都去写同一份第三方文档」时。
- 服务异常崩溃时运行中会话的转写与 commit 不保证；正常关停有终止收尾
  兜底。
- 会话面板不承载档案（per-boot 窗口），跨重启回看走会话历史。

**得到的**

- 多个未决点并行推进，不再被单会话互斥串行化。
- 注意力路由：面板（谁在跑）、徽标（谁在等我）、提示条（谁完成了）。

**不变的**

- 既有会话语义逐会话适用：`spec-00001-FR-12`（终端流式与尺寸）、
  `spec-00001-FR-13`（写权限）、`spec-00001-FR-14`（一会话一 commit）、
  `spec-00001-FR-16`（启动失败）、`spec-00001-FR-54`（会话历史）、
  `spec-00001-FR-55`（agent 可选）。
- `rule-00001-docs-workflow` 的状态流转、可澄清/可审计类型集不变。
- `decision-00008` 其余各行不受影响，仅 §3「多会话并行」一行被推翻。

- `spec-00003-whiteboard-parallel-sessions`：全部 FR 按本决定落地；其
  Open Questions 由本决定逐条关闭。
- `spec-00001-docs-whiteboard`（修订轮任务，由 plan 轮列出）：FR-18 改写
  为并发模型、FR-49 的入口/禁用原因拆分、FR-50 删除单会话复述、FR-21
  扩展多会话、FR-15 校验扩展 `max_sessions`、§6 移除「多会话并行」范围
  外条目。
- `design-00001-docs-whiteboard`：会话注册表由单例槽位改多会话、终止与
  会话 API 携带会话标识、静默阈值常数、commit 串行队列、关停终止收尾。
- `design-00002-whiteboard-ui`：会话面板、徽标与节点标记、终端切换。
- `whiteboard.config.yaml`：新增 `max_sessions: 3`。
- `CONTEXT.md`：新增「会话面板」「等待输入」；修订「呈现状态」「流程
  配置」「会话前快照」「终止」四条定义。
- 原地追注（随本决定已落笔）：`decision-00008` 摘要、§3「多会话并行」行、
  §4「未做多会话并行」；`decision-00007` §4 的单会话复述；
  `decision-00006` §2 第 7 条、§4「唯一会话槽」、§5 实录门槛的豁免注记。
- 站立约束：不得重新引入全局单会话互斥；不得把发起互斥扩展到关系文档。
