# Docs 白板 PRD

## 一句话概述

一个本地单人使用的白板式 Web 界面，把 `docs/` 目录可视化为节点图，人在图上
评审、编辑、推进文档，agent（Claude Code / Codex）在内嵌终端里代写文档。

## 愿景与目标

docs 体系的关系、状态与流程规则目前埋在 front matter 和散文规范里，靠人记忆
和手工遵守。白板把它们变成看得见、点得动的界面：

- 打开白板即可看清全部文档的依赖链、状态分布与流程卡点。
- 流程规则产品化：下一步是什么、front matter 怎么填，由工具保证而非人记忆。
- "人评审、agent 执行"的循环收敛到一个界面，评审动作显式留痕。

Markdown 文件始终是唯一事实来源；白板只是仓库的视图与操作台，可随时丢弃重建。

## 角色

- **文档负责人**（唯一人类角色）：浏览节点图、评审（接收/澄清/审计）、编辑
  文档、发起下一步。
- **agent**（Claude Code / Codex 等本地 CLI）：在受限权限下生成或修改
  `docs/` 下的文档。

## 范围

### In scope（MVP）

- 本地服务 + 浏览器的单人工具，运行在一个 docs 体系仓库之上。
- 节点图的解析、渲染与自动布局。
- 节点上的状态展示与切换、Markdown 编辑、评审动作。
- 按流程配置推进下一步，调起本地 agent CLI，内嵌终端交互。
- 变更自动 commit，评审动作留痕。

### Out of scope

- 多人协作、远程部署、账号体系。
- 「拒绝」评审动作（已裁剪；评审动作为接收/澄清/审计，第十轮由
  decision-00007 补入审计）。
- agent 修改 `docs/` 之外的内容（代码、根规范文档等）。
- 在白板内编辑 `docs/` 之外的文件。

## 功能需求

1. **节点图**：解析 `docs/**/*.md` 的 front matter，文档为节点、关系字段
   （`parent`、`implements`、`informs` 等）为边，自动排版布局。
2. **节点信息**：节点上显眼展示文档类型、id、标题与 `status`。
3. **浮窗工具栏**：点击节点弹出浮窗，提供编辑、状态切换、评审、答疑、推进
   下一步等入口。
4. **Markdown 编辑**：在前端 Markdown 编辑器中编辑文档正文，保存即写回对应
   文件。
5. **状态切换**：只允许 docs 体系定义的合法流转（living doc 与 work item 两套
   词汇），非法流转不可选。
6. **评审动作**：
   - **接收** = promote（living doc `draft → active`，work item `draft → open`）；
   - **澄清** = 保持 `draft`，由 agent 会话带着该文档及其关系文档逐题向
     负责人提问，确认的未决点记入 Open Questions、既定结论直接修订文档
     （第八轮由 decision-00006 改写，原「手动记录待澄清点」语义废弃）；
   - **审计** = 保持 `draft`，对 `draft` 的 spec/rule/design 发起 agent
     会话，以未撰写者立场对照文件夹 README 先审结构与文法、再审内容，
     未决发现记入 Open Questions、既定结论直接修订正文（第十轮新增，
     decision-00007）。
7. **推进下一步**：节点右侧「+」按钮按流程配置弹出候选的下一步文档类型
   （如 idea → prd、spec → plan），选定后发起 agent 会话生成新文档。
8. **agent 会话**：通过本地 CLI 调起 Claude Code / Codex，前端内嵌终端实时
   交互查看；agent 权限限定为 `docs/` 下全部权限，不可改动其外内容。
9. **front matter 保障**：白板发起的新文档自动带上正确的 front matter
   （id 规则、`parent` 指向来源节点等）。
10. **流程配置**：文档类型、下一步映射、关系字段等流程规则由配置文件定义，
    白板读配置而不解析散文规范。
11. **自动留痕**：白板上的编辑与状态切换自动 commit；评审动作（接收/澄清/
    审计）与答疑必须留下可追溯的记录（答疑的记录自第二十一轮起是板外的
    问题列表与会话历史，不再经 commit——spec-00005）。
12. **答疑**：在任意状态的节点上向 agent 提问，headless 后台作答，按问
    积累成可浏览的问题列表、可在问内追问；只读——不修改文档，修订走
    编辑、推进或澄清；不是评审动作，不改变状态（第八轮新增，
    decision-00006；第二十一轮改 headless 只读形态，decision-00012 /
    spec-00005）。
13. **终止会话**：运行中的 agent 会话可随时被用户终止，留痕照常；卡住的
    会话不得锁死白板（issue-00010 补齐）。
14. **plan 的 resolved 门**：plan 从 `open` 促为 `resolved` 时，以指向该
    plan 的 record 验收行为证据，交付范围内每个需求条目须为已验证，缺口
    逐条点名并拒绝流转（第十轮新增，decision-00007）。
15. **新建入口文档**：在白板上直接新建流程入口类型的文档（流程配置声明
    的全部入口类型，decision-00014 补齐诞生通路后现为十类）：id 自动
    取号、模板预填、保存即建档并留痕；共写模式下确认即建档并接续会话
    （第十一轮新增，decision-00008；第二十二轮增共写模式，spec-00006）。
16. **会话历史**：已结束会话的转写与元数据落盘、重启不丢，可在白板中列出
    与查看（第十一轮新增，decision-00008）。
17. **agent 选择**：流程配置声明多个 agent CLI 时，发起会话可指定其中一个，
    未指定取第一个（第十一轮新增，decision-00008）。
18. **共写**：对一份 `draft` 文档（work item 亦可在 `open`）发起多轮共写
    会话：编辑器与终端同屏的工作区，agent 按用户的意图与材料起草或改写
    正文；等待输入期间可手改保存，下一轮自动附手改注记；发起时可给材料
    （粘贴文本、仓内文档 id、仓库外路径与 URL，仓外读取由所选 CLI 自身
    的权限机制裁决）；写域仅限目标文档与合式新建的 reference 文档，由
    收束过滤保证，会话收束单次 commit；不是评审动作，不改变状态
    （第二十二轮新增，decision-00015 / spec-00006）。
19. **文内标注**（指针）：选区标注、统一提交与 question/issue 双通路的
    进展追踪属 `prd-00002-doc-annotations`（独立立项，spec-00007
    承载）——能力清单不在此复述，避免两清单漂移（第二十三轮）。

## 用户体验期望

- 打开即见全图，无需手工摆放节点；图随文档规模增长仍可读（缩放、聚焦）。
- 节点的状态一眼可辨（如按 status 着色）。
- 在白板之外直接改文件后，白板刷新即可反映最新状态，不产生冲突数据。
- 内嵌终端的体验接近本地终端：实时输出、可输入交互。

## 风险与依赖

- **依赖**：本地已安装的 agent CLI（Claude Code / Codex）；git 仓库；docs
  体系规范（`docs/README.md`）。
- **脏数据容错**：front matter 缺失、非法或关系断链的文档如何呈现与修复，
  决定白板在真实仓库上的可用性。
- **并发写入**：内嵌终端里的 agent 与白板编辑器可能同时写同一文件，需要防止
  相互覆盖。
- **权限约束的可靠性**：「agent 只能写 `docs/`」依赖 CLI 的权限机制传递，
  是实现上的关键风险点。
- **自动 commit 的噪音**：频繁小提交可能污染 git 历史，粒度需在设计时权衡。
