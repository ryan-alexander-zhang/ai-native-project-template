## Detailed Acceptance Path

1. T1/T2 的每份修订文档回到 `active`，全量文档零解析诊断 → verify:
   `npm test` 契约测试通过。
2. 标注全链路在真实 CLI 上走通（加注 → 改删/重新选区 → 统一提交 →
   question 答疑作答 + issue 自动流转与共写逐条修订 → 收束 → 进展
   呈现与定位）→ verify: 集成测试与手工冒烟。
3. 交付范围内每条 AC 在 record 有通过行 → verify: record 验收清单
   （`parent` 指向本 plan）。
4. 本 plan 过 `open → resolved` → verify: resolved 门放行
   （`rule-00001-BR-25`）。
